# Aimili Gateway V1-D 高级设置、统一凭据与自动代登录设计

## 1. 文档状态

- 日期：2026-08-27
- 项目：`aimili-gateway`，并涉及 `aimili-vpngate` 的版本化控制 API
- 使用范围：个人单管理员，不考虑多租户或 RBAC
- 聊天设计：用户已确认采用推荐方案
- 文档状态：等待用户最终审核；审核通过前不得制定实施计划、编码或部署
- 前置设计：`2026-08-26-online-proxy-pools-design.md`

本文取代前置设计中关于近期重新认证、强制 mixed 来源 CIDR、原后台独立凭据体验和高级设置页面的规定。在线代理池资源模型、AimiliVPN 与 3x-ui/Xray 独立运行、`agw-` 所有权边界以及 512 MiB 单在线出口策略继续有效。

## 2. 目标与术语

本阶段交付一个更简洁的高级设置区域，并把个人用户需要维护的三套管理凭据收敛为一个受支持的账户修改入口：

1. Gateway、AimiliVPN 原后台和 3x-ui 原后台使用相同用户名与密码。
2. 通过 `sudo aimili-gateway-account` 修改统一用户名或密码时，三个服务同步更新。
3. 用户已登录 Gateway 后，点击原后台入口即可直接进入目标后台，不再手动输入密码或点击登录。
4. Gateway 原生高级页面仍是日常入口，原后台保留完整功能并作为维护或专家模式。

该方案称为**统一凭据＋服务端自动代登录**，不称为真正 SSO：三个服务仍各自验证账户、签发自己的 Cookie 并维护独立会话。相同密码、反向代理保护、服务端代登录都不等同于覆盖全部页面的单点登录协议。

“始终一致”定义为：通过受支持的统一账户命令完成的变更，只有在三个账户均验证为新值后才报告成功。跨进程更新无法获得数据库级原子性；若服务故障或人工直接在原后台改密导致短暂漂移，系统必须显式标记“需要修复”、停止自动代登录并提供统一修复流程，不能谎报一致。

## 3. 范围与非目标

### 3.1 本次范围

- 删除高级设置中的“安全确认”卡片和近期重新认证业务要求。
- 登录会话有效时允许复制、导出、启用、换 IP、回收和修改高级设置。
- 将 SOCKS5H 来源限制改为可启用或关闭的设置；新安装默认启用，现有安装保留启用状态。
- 新建 Gateway 原生 `AimiliVPN 设置` 与 `3x-ui 设置` 页面，承载经过适配器支持的常用设置。
- 在高级设置中保留两个原后台入口，并以服务端自动代登录直接进入。
- 扩展统一账户命令，实现三账户预检、同步、验证、回滚、漂移检测和修复。
- 简化代理池面向用户的状态文案，同时保留完整后端状态机。
- 显示当前在线数、候选数和只读容量信息。
- 修订历史验收文档的后续状态，不改写历史时点的事实。

### 3.2 明确不做

- 不实现 OIDC、SAML、OAuth 或覆盖全部页面的真正 SSO。
- 不在浏览器 DOM 中自动填密码，不使用前端脚本点击原登录按钮。
- 不删除 AimiliVPN 或 3x-ui 原登录页；自动代登录失败时必须保留手动登录回退。
- 不重写 3x-ui、Xray 或 AimiliVPN 核心，不合并 Go 与 Python 进程。
- 不接管、覆盖或删除非 `agw-` 的 3x-ui/Xray 资源。
- 不在本阶段把 512 MiB VPS 的生产在线容量提升到两个或更多。
- 不把本阶段扩大为服务器全面改造。

## 4. 页面信息架构

主导航继续为“VPN 节点池”“SOCKS5H 代理池”“高级设置”和账户菜单。高级设置采用紧凑分组，不显示 Aimili Gateway、AimiliVPN、3x-ui 顶层状态卡。

### 4.1 SOCKS5H 访问控制

- 顶部使用“启用来源限制”开关。
- 开启时显示 CIDR 列表编辑器、格式帮助和当前生效状态。
- 关闭时隐藏 CIDR 编辑器，持续显示风险说明：SOCKS5H 仍要求用户名和密码，但协议本身不加密，任何公网来源都可以尝试认证。
- 保存后显示“正在应用 / 已生效 / 应用失败”，不能只写数据库后立即显示成功。
- 不再要求输入 Gateway 密码或 TOTP，不以新的确认弹窗变相恢复“安全确认”。

### 4.2 后台管理

每个底层服务使用一张紧凑入口卡：

- `AimiliVPN 设置`：进入 Gateway 原生设置页，沿用 Gateway 会话。
- `进入 AimiliVPN 原后台`：通过自动代登录直接进入原页面。
- `3x-ui 设置`：进入 Gateway 原生设置页，沿用 Gateway 会话。
- `进入 3x-ui 专家模式`：通过自动代登录直接进入原页面。

页面只显示账户同步状态，例如“已同步”“需要修复”“版本不兼容”；不显示密码、Cookie、后台随机路径或自动化令牌。自动登录不可用时提供“查看修复说明”和“打开手动登录页”，不能无限重试。

### 4.3 运行容量

只读显示候选数、在线数、生产上限和低内存说明。当前 `ny` 为 512 MiB，生产上限保持 1。页面不提供任意容量输入框，也不把代码上限 64 描述为稳定容量。

## 5. 代理池状态呈现

后端继续保存以下精确状态，避免跨服务操作失败后丢失恢复依据：

| 后端状态 | 主列表文案 | 用户含义 |
| --- | --- | --- |
| `standby` | 可选节点 | 候选已通过 AimiliVPN 目录验证，但未占用 OpenVPN、Xray 入站或公网端口，不能复制连接地址 |
| `ready` | 已启用 | VLESS、SOCKS5H、代理 DNS 与出口一致性均已真实验证 |
| `provisioning`、`rotating`、`disabling` | 处理中 | 正在创建、换 IP 或回收，暂不可操作 |
| `degraded` | 故障 | 资源存在但最新链路检测失败，可以检测或换 IP |
| `repair_required` | 故障 | 跨服务操作或补偿不完整，需要专门修复；详情明确标为“需要修复” |

筛选器使用面向用户的四类文案；详情抽屉和运维记录保留精确技术状态与脱敏错误码。只有 `ready` 允许复制或导出。

## 6. 统一凭据模型

### 6.1 唯一受支持的修改入口

`sudo aimili-gateway-account` 是统一用户名与密码的唯一受支持修改入口。菜单调整为：

1. 查看统一账户、Gateway TOTP 和三服务同步状态。
2. 修改统一用户名。
3. 生成统一随机密码。
4. 设置统一自定义密码。
5. 启用或重新登记 Gateway TOTP。
6. 关闭 Gateway TOTP。
7. 修复三账户同步。
8. 撤销 Gateway 登录会话。

原后台仍保留自身账户功能，因为本项目不删除上游功能；若用户直接在原后台修改账户，Gateway 无法知道新明文密码，必须检测为漂移并要求通过统一命令重新对齐。原后台页面和项目文档应明确提示不要从这里改账户。

同步状态在 Gateway 启动、每次账户操作、每次自动代登录前以及每 6 小时低频检查时更新。检查只验证安全用户名摘要、能力和统一凭据能否登录，不读取或返回上游密码。低频检查失败只关闭自动代登录并告警，不影响代理数据面。

### 6.2 存储边界

- Gateway 登录验证继续只使用 Argon2id 密码哈希。
- 为调用两个原后台和执行自动代登录，Gateway 使用主密钥加密保存一份统一用户名与密码；密文按独立用途绑定，不能跨用途解密。
- 明文只在受限进程内短暂存在，使用后尽可能清零；不得写入 SQLite 明文字段、JSON 配置、命令行参数、环境变量、日志或审计正文。
- AimiliVPN 仍按其自身实现保存 UI 凭据；3x-ui 仍按上游实现保存账户。Gateway 不直接写它们的数据库或配置文件。
- 现有 `xui-automation.json` 仅作为一次迁移输入。迁移验证完成后，Gateway 运行时改从加密统一凭据读取；是否删除旧文件由部署迁移在备份和回退验证后决定。

### 6.3 第一次对齐

现有 Gateway 密码无法从哈希恢复。升级后的首次运行将同步状态标为“等待统一重置”，并保留现有 Gateway 登录。用户必须执行一次随机或自定义统一密码重置；命令验证三个服务均接受新凭据后，才启用自动代登录。

## 7. 三账户同步事务

所有账户变更持有全局账户互斥锁，并使用单次操作记录保存阶段和脱敏结果。

### 7.1 预检

1. 读取当前加密统一凭据和 Gateway 管理员版本。
2. 探测 AimiliVPN 控制 API 与 3x-ui 账户更新能力。
3. 使用旧统一凭据分别完成 AimiliVPN 与 3x-ui 登录验证。
4. 验证新用户名和密码同时满足三个服务的交集约束。
5. 任一预检失败时不修改任何账户。

### 7.2 更新与验证

1. 通过 AimiliVPN 回环控制 API 更新 UI 账户并撤销其旧会话。
2. 使用已认证的 3x-ui 适配器调用版本化账户更新端点，并撤销或失效其旧会话。
3. 分别使用新凭据重新登录两个原后台。
4. 在一个 Gateway SQLite 事务中更新密码哈希、加密统一凭据、用户名、安全版本和同步状态，并撤销 Gateway 旧会话。
5. 再执行一次三方用户名与登录能力核对，全部通过才报告成功。

随机密码只在当前受限终端显示一次；自定义密码隐藏输入并二次确认。密码和用户名不得作为 CLI 参数传入。

### 7.3 回滚与修复

- 外部服务更新失败时，使用旧凭据反向恢复已更新服务并验证。
- Gateway 本地事务失败时，同样尝试恢复两个外部服务。
- 回滚全部验证成功时报告“变更失败，原账户已恢复”。
- 回滚不完整时记录 `repair_required`，停止两个自动代登录入口，但不停止代理服务、Xray 或现有在线节点。
- “修复三账户同步”要求用户输入一个新的统一密码，不尝试查询或显示任何当前密码；修复流程重新执行能力探测、三方更新和验证。

## 8. AimiliVPN 账户与会话契约

AimiliVPN 现有控制 API 只支持候选和槽位。V1-D 在同一回环监听、Bearer token 和封闭字段模型下增加账户能力：

- 能力探测声明账户更新与会话签发是否受支持。
- 账户更新接收新用户名和密码，原子替换 UI 凭据并清除旧 UI 会话；响应不返回凭据。
- 会话签发只接受已认证的 Gateway 控制调用，创建短生命周期原后台会话并返回不透明会话值；不返回 UI 密码或后台路径。
- 控制 API 继续拒绝非回环来源，限制请求体大小，并使用稳定脱敏错误码。

Gateway 收到不透明会话值后，只通过 HTTPS 响应设置限定到 AimiliVPN 公网子路径的 `Secure`、`HttpOnly`、`SameSite=Strict` Cookie，然后跳转。Cookie 不进入 JSON、URL、HTML或 JavaScript。

## 9. 3x-ui 账户与会话桥接

3x-ui 适配器继续只通过回环 HTTP API 工作，不直接写 `x-ui.db`：

1. 获取 CSRF token，并使用旧统一凭据登录。
2. 调用已验证版本的账户更新端点。
3. 使用新凭据重新获取 CSRF 并登录，确认更新成功。
4. 自动代登录时在服务端 Cookie Jar 中完成登录，只提取经过白名单验证的认证 Cookie。
5. Gateway 将认证 Cookie重写为公网专家模式精确子路径，并强制 `Secure`、`HttpOnly` 与 `SameSite=Strict` 后跳转。

浏览器进入 3x-ui 后自行获取页面所需 CSRF token。若 3x-ui 返回未知 Cookie、未知重定向、要求自身 TOTP 或端点契约不匹配，桥接必须失败关闭并回退到手动登录，不能把上游响应头或 Cookie原样透传。

## 10. 自动代登录浏览器流程

原后台入口不是普通 GET 链接，而是 Gateway 同源表单或按钮触发的 POST：

1. Gateway 验证当前登录会话、同源 `Origin` 和 CSRF token。
2. 检查目标服务能力、账户同步状态和入口路径配置。
3. 在服务器回环网络中创建目标原后台会话。
4. 只在响应头中设置目标路径的 HttpOnly Cookie。
5. 返回 `303 See Other` 跳转到目标后台入口。

入口 POST 不接受目标 URL、用户名或密码参数，防止开放重定向和凭据选择。响应使用 `Cache-Control: no-store`。Gateway 审计只记录目标服务、成功或脱敏错误码和时间，不记录 Cookie、路径或凭据。

## 11. TOTP 与会话边界

- Gateway TOTP继续可选，仅保护 Gateway 登录；当前个人配置可保持关闭。
- AimiliVPN没有对应 TOTP 能力。
- 3x-ui 自身 TOTP 必须保持关闭，才能使用自动代登录。若用户在专家模式中启用，系统显示“不兼容自动代登录”并降级为手动登录。
- 三服务只同步用户名和密码，不宣称同步第二因素。
- 删除“近期重新认证”后，Gateway 会话超时、登录限速、CSRF、同源检查、安全 Cookie和 `no-store` 继续保留。
- 退出 Gateway 不主动退出两个原后台的既有独立会话；高级设置提供清晰说明。账户变更会撤销或失效三方旧会话。

## 12. SOCKS5H 来源限制模型

设置模型由“CIDR 列表非空即启用”改为显式的 `enabled` 与 `cidrs`：

- `enabled=true`：只允许配置 CIDR以及必要的回环探测来源，其他来源进入受管黑洞出站。
- `enabled=false`：不添加 mixed 来源白名单和默认拒绝规则，所有公网来源均可尝试 SOCKS5H 用户名密码认证。
- 无论开关状态，mixed 入站都必须启用强随机用户名与密码，且 SOCKS5H URI仍按秘密处理。
- CIDR 继续要求规范网络前缀；开启时列表不能为空，仍拒绝以全网 CIDR伪装成“开启限制”。
- 新安装默认开启；迁移时只要旧表存在 CIDR，就迁移为开启，避免升级后意外放宽。

保存设置必须更新所有现有 `agw-` mixed 路由，而不只影响新建节点。协调器对每个在线组计算新指纹、依次应用并验证 SOCKS5H；任一组失败时回滚本次已修改组并把设置标记为未生效或需要修复。候选目录和 VLESS 不因该操作重建。

## 13. Gateway 原生高级页面边界

Gateway 原生页只暴露适配器已明确支持、能验证且能安全回滚的常用信息与操作。V1-D 字段固定为：

- AimiliVPN：有效候选总数、住宅/机房数量、最后刷新时间、受管槽位数量；操作仅为刷新候选目录、检测受管槽位和进入原后台。
- 3x-ui：Gateway 受管 VLESS、mixed 和出站数量、所有权指纹核对结果、最后检测时间；操作仅为检测受管资源、修复受管资源漂移和进入专家模式。

未知版本或缺少能力时页面进入只读降级，展示维护提示；不透传上游任意设置对象，不允许借 Gateway 修改非受管资源。其他底层设置继续在原后台完成，实施计划不得顺便扩充为完整原后台重写。

## 14. 更新兼容性

- AimiliVPN 控制 API 使用版本号与能力列表；缺少账户能力时不执行同步或自动代登录。
- 3x-ui 适配器按已验证版本维护账户更新、登录、CSRF、Cookie与重定向契约；未知版本先运行无副作用探测。
- 上游更新不兼容时，代理数据面和现有在线节点继续运行，原后台入口降级为手动登录，账户同步命令在预检阶段停止。
- 部署前后均执行契约测试；不得因自动代登录失败重装 3x-ui、覆盖数据库或删除非受管资源。
- 自动代登录功能不能成为 AimiliVPN、3x-ui 或 Xray启动依赖。

## 15. 512 MiB 容量策略

当前代码支持多个在线组，但 `ny` 生产 `maxProxyGroups` 保持 1。每个在线组增加一个 OpenVPN/TUN 槽位、一对 Xray 入站、端口、路由和探测开销。最新只读检查显示四服务为 `active`、无失败单元、可用内存约 186 MiB、Swap 已使用约 135 MiB；这些数据不足以证明两个常驻组稳定。

V1-D 部署和高级设置验收完成后，另立容量实验：`1 → 2`，至少验证双组真实 VLESS、SOCKS5H、代理 DNS、服务逐个重启、持续资源占用、内核 OOM记录和回退。只有获得新的明确授权且全部通过，才把生产上限改为 2。

## 16. 数据迁移与部署

1. 备份 Gateway 数据库、加密主密钥引用、AimiliVPN UI 账户配置、3x-ui 配置和 Caddy 文件；备份不得输出内容。
2. 新增统一凭据密文、同步状态、账户操作记录和 SOCKS5H 开关迁移。
3. 保持旧 Gateway 管理员哈希与会话可用，但自动代登录初始为“等待统一重置”。
4. AimiliVPN 与 3x-ui 适配器先完成能力探测，未通过时不开放入口。
5. Caddy只保留现有精确原后台路由和 Gateway 路由，不新增 Basic Auth，也不声称 SSO。
6. 部署后由用户执行一次统一密码重置，完成三账户对齐。
7. 验证通过后才清理不再需要的旧自动化凭据文件；回退所需备份继续使用 root-only 权限。

Gateway 服务仍以非 root 用户运行，只允许访问回环网络与自身状态目录。账户管理瞬态单元新增的网络权限仅限 `AF_INET/AF_INET6` 与 localhost，并加载必要的 AimiliVPN 控制凭据；不授予 shell、任意命令、任意文件写入或公网访问。

## 17. 错误处理与审计

用户可见错误只使用稳定分类：服务不可用、版本不兼容、账户不同步、自动登录失败、设置应用失败、需要修复。上游响应正文、堆栈、Cookie、用户名以外的凭据内容和后台路径不得返回前端。

审计记录以下事件：统一账户预检、同步成功或失败、回滚结果、修复结果、自动代登录成功或失败、来源限制变更及应用结果。审计不得包含密码、TOTP 秘钥、Cookie、UUID、私钥、随机后台路径、候选原始 ID或完整连接地址。

### 18.2 VPS 验收

- 升级前后四服务独立运行，非受管 3x-ui/Xray 资源不变。
- 统一随机密码与自定义密码分别至少验证一次三方同步，输出中不泄露秘密。
- 登录 Gateway 后，两个原后台入口均无需人工输入即可进入；手动登录回退仍可用。
- 账户变更后三方旧会话失效，新凭据均可登录。
- SOCKS5H 来源限制开启时未授权来源拒绝；关闭时经过用户名密码认证的外部来源可以使用代理 DNS；重新开启后再次拒绝未授权来源。
- 删除近期重新认证后，复制、导出、启用和换 IP 沿用户原路径通过。
- 当前单在线节点的 VLESS、SOCKS5H、代理 DNS、出口一致性和服务重启恢复再次通过。
- 浏览器控制台没有密码、Cookie、路径或静态资源错误。

完成声明必须区分自动测试、本机浏览器、服务器端真实链路与外部用户客户端结果。局部 API成功不能代替用户原路径端到端验收。
