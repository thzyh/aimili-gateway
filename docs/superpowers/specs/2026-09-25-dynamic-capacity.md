# VPS 动态容量与高级设置

## 目标和事实来源

“当前有效节点”是探测结果，不能由管理员填写。管理员可以设置有效节点常规目标、紧急保护上限和普通出口位数量；主连接始终单独计数。aimili-egress 的受管数据目录保存用户期望值和槽位配置，Gateway 从受控 API 读取并在运行时更新准入上限。页面不得用固定的 64、150 或 4 伪造当前状态。

## 自动上限

aimili-egress 从 `/proc/meminfo`、CPU 数量和一分钟负载读取当前主机事实。每个新普通出口位预留约 64 MiB，且不动用 256 MiB 的整机余量；CPU 上限为每核四个普通出口位，软件上限为 16。可用内存和负载下降时，允许新增的出口位上限及候选池目标上限收紧；资源恢复后重新计算并回升。已经配置的出口位不会因瞬时压力被自动删除。候选池的常规目标至少覆盖现有出口、主连接和两个专属备用的需求。上述数值是保守准入预算，不是“可承受并发量”的保证。

用户配置保留为期望值；运行时采用 `min(期望值, 当前自动上限)`。没有用户覆盖时，期望值跟随自动上限。每次查询容量和候选目录、以及每轮候选池维护都会重新采样。高级设置可手动刷新最新上限。超出当前上限的修改会被拒绝，并返回当前上限；资源恢复时无需管理员重新设置上限。

## 修改普通出口位的边界

新增出口位前，egress 核对 3x-ui 协议事务白名单以及 UFW 中相应的公网 VLESS、mixed 端口；缺任一项就返回 `capacity_upgrade_required`，提示按当前域名运行最新签名安装器续装。新安装器提前准备 16 个受管端口的允许规则，未启用的端口没有监听进程。

减少普通出口位前，Gateway 检查既有受管组数量及其具体槽位编号；仍在使用的槽位不能被移除。egress 先保存新的槽位设置，Gateway 再更新运行时准入上限；后者失败时尝试回滚 egress。保存文件失败时回滚槽位，回滚失败会明确报告 `repair_required`。新增槽位的就绪状态独立回读，页面区分“已配置”和“真实就绪”，不把待验证出口显示为成功运行。Gateway 在新槽位通过真实出网检查后再继续受管资源编排。

## 发布与验收边界

本功能改动包含 Gateway、aimili-egress、前端与一键安装器；必须作为完整项目版本发布，不能只更新网页。既有部署的防火墙和协议白名单可能只覆盖旧出口数量；此时页面给出同域名续装路径。512 MiB 生产 VPS 的已运行 4+主1 保留，验收时不能自动增加真实 OpenVPN 数量。大规格 VPS 的扩容仍应逐个检查出网、订阅、3x-ui/Xray、服务重启和资源压力，失败应保持当前健康出口并标记未就绪。
