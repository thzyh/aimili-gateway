## 2. 已确认的产品定义

Aimili Gateway 的主用途不是展示三个服务是否在线，而是把 AimiliVPN 的可用出口组织成能够直接使用的 VLESS 和 SOCKS5H 代理。

用户的日常目标是：

1. 只登录一次 Aimili Gateway。
2. 查看 AimiliVPN 当前有效节点池中所有已验证的国家和出口 IP。
3. 按国家和出口类型浏览住宅、移动网络及机房出口。
4. 从目录中启用有限数量的代理组。
5. 每个启用的代理组同时拥有一个 VLESS Reality 入站和一个 mixed 入站。
6. 两个入站通过受管 Xray 出站和路由规则连接到同一个 AimiliVPN 多出口槽位。
7. 复制或导出经过验证的 VLESS 和 SOCKS5H 连接地址。
8. 在不改变入口地址的情况下检测状态或更换同国家、同类型的出口 IP。
9. 在 Gateway 的高级设置中管理 AimiliVPN 和 3x-ui 的常用高级功能。

服务健康状态仍保留，但缩小为页面顶部状态条和故障提示，不再占据首页主体。

## 3. 术语和关键区别

### 3.1 候选节点、出口槽位和出口 IP

- 候选节点：AimiliVPN 当前有效节点池中最近一次 OpenVPN 探测成功的节点。
- 出口槽位：AimiliVPN 为一个启用代理组运行的独立 OpenVPN、策略路由和本地 SOCKS 代理单元。
- 出口 IP：流量真正离开 AimiliVPN 槽位后，由外部检测服务观察到的公网 IP。

VPNGate 节点登记 IP 可能与 NAT 后的真实出口 IP 不同。页面、分类和最终验收以实际观察到的出口 IP 为准，不以节点登记 IP 代替。

### 3.2 入口地址和出口 IP

客户端连接的是 VPS 域名与 Xray 入站端口。住宅或机房 IP 是目标网站看到的出口，不是客户端直接连接的 VLESS 或 SOCKS5 服务器地址。

一个代理组在任意时刻建立以下映射：

| 稳定资源 | 当前动态资源 |
|---|---|
| 国家、出口类型、VLESS 端口、mixed 端口、客户端身份 | AimiliVPN 节点、槽位连接、实际出口 IP |

更换出口 IP 只替换动态资源，不改变已经复制到客户端的 VLESS 或 SOCKS5H 入口地址。

### 3.3 mixed 与 SOCKS5H

`mixed` 是 Xray 服务端入站协议，可接受 SOCKS5 和 HTTP 代理连接。`socks5h` 是客户端 URI 语义，表示域名通过 SOCKS5 代理解析，不是新的服务端协议，也不提供传输加密。

## 4. 范围和非目标

### 4.1 V1 后续范围

- 全量展示 AimiliVPN 当前有效节点池中的国家和候选 IP。
- 将 `mobile` 归入住宅，将 `hosting` 或代理/托管特征归入机房。
- 分类未知、没有本轮节点池成功探测记录或尚未完成实际出口复核的候选只显示在高级设置，不允许直接启用。
- 每个国家和出口类型最多启用一个稳定代理组。
- 每个代理组建立一对 VLESS Reality 与 mixed 入站。
- 所有受管 VLESS 入站复用一个全局客户端身份。
- 所有受管 mixed 入站复用一个全局用户名和密码。
- 维护受管 Xray SOCKS 出站、路由规则和连接信息。
- 支持检测、换 IP、禁用、修复、复制和 TXT 导出。
- Gateway 原生高级设置页面覆盖 AimiliVPN 和 3x-ui 的常用维护能力。

### 4.2 明确非目标

- 不为每一个原始 VPNGate 候选 IP 同时运行独立代理组。
- 不保证互联网中所有 VPNGate 节点都进入目录；“全部”指 AimiliVPN 当前有效节点池中的全部已验证记录。
- 不提供多租户、共享账户、角色或计费。
- 不重写 OpenVPN、Xray 或 3x-ui 核心。
- 不直接修改 `x-ui.db`。
- 不把 Python 与 Go 服务合并为一个进程。
- 不删除 3x-ui 或 AimiliVPN 原生页面和功能。
- 不同步三个系统的用户名和密码。
- 不把相同密码、Caddy 外层认证、表单自动填写或 Cookie 注入描述为 SSO。
- 不提供任意 Xray JSON 编辑器或服务器全面运维。
- 不提供匿名公网 SOCKS5 代理。

## 5. 容量模型

目录与在线代理组分离：

- 目录可以展示任意数量的有效国家和候选 IP。
- 只有用户明确启用的代理组才占用 AimiliVPN 槽位、两个 Xray 入站和两个公网端口。
- 一个代理组固定消耗一个 AimiliVPN 多出口槽位。
- Gateway 部署配置 `maxActiveProxyGroups` 的默认值为 4，作为当前 512MB VPS 的初始活动上限。
- 生效上限取部署配置、AimiliVPN `MAX_EXIT_SLOTS` 和两个端口池可用配对数的最小值。
- 达到上限后，页面仍显示全部目录，但必须先禁用一个代理组才能启用新的国家或类型。
- Gateway 高级设置只显示容量，不直接提高上限。提高 `maxActiveProxyGroups` 属于单独的部署配置调整；必须先完成内存、CPU、文件描述符、OpenVPN 稳定性和并发流量验证。

V1 不实现按请求临时启动 OpenVPN 的“冷启动代理”，也不在容量不足时静默把流量切到错误国家或错误类型。

## 6. 代理组模型

代理组的稳定键为 `国家代码 + 出口类型`，出口类型只有：

- `residential`：AimiliVPN 的 `residential` 和 `mobile`。
- `datacenter`：AimiliVPN 的 `hosting`，包括检测为代理或托管网络的出口。

每个代理组包含：

- 稳定非秘密标识。
- 国家代码和中文显示名。
- 出口类型。
- 启用状态。
- AimiliVPN 槽位稳定编号。
- 当前节点脱敏标识。
- 当前实际出口 IP。
- VLESS 和 mixed 入站稳定标识与端口。
- Xray 受管出站和路由稳定标识。
- 配置指纹、最近检测时间、最近换 IP 时间和错误类别。

代理组状态为：

- `provisioning`：正在创建。
- `ready`：两种协议和真实出口均验证通过。
- `rotating`：正在更换同国家、同类型出口。
- `degraded`：资源存在，但一项或多项健康检查失败。
- `repair_required`：跨服务写入部分成功，禁止重复修改，等待修复或回滚。
- `disabling`：正在受控删除受管资源。

只有 `ready` 状态允许复制或导出连接信息。

## 7. 受管资源与所有权

Gateway 只修改自己创建并带有稳定 `agw-` 命名空间的资源：

- AimiliVPN 槽位绑定记录。
- VLESS Reality 入站。
- mixed 入站。
- Xray SOCKS 出站。
- 从两个入站标签到对应 SOCKS 出站的路由规则。

既有 3x-ui 入站、客户端、出站和路由均视为非受管资源：

- 不自动接管。
- 不删除。
- 不覆盖字段。
- 不因名称相似而推断所有权。
- 可以在高级设置中只读显示。

如果专家模式修改了受管资源，Gateway 通过配置指纹发现漂移，停止自动写入并进入 `repair_required`，由用户选择恢复 Gateway 配置或放弃该资源的管理权。

## 8. VLESS 设计

### 8.1 全局客户端

所有受管 VLESS 入站复用一个全局 VLESS 客户端身份和一个受管 Reality 模板。由于 3x-ui/Xray 的客户端配置属于入站，每个 VLESS 入站仍会包含一份相同身份的客户端记录，因此 3x-ui 可能在每个入站显示“1 个客户端”；用户不需要分别创建或维护它们。

全局身份、Reality 私密材料和可导出连接参数：

- 使用 Gateway 主密钥加密后保存。
- 明文不进入普通配置、日志、审计或 Git。
- 只在创建 3x-ui 资源和用户主动显示、复制、导出时短暂解密。
- 重置全局身份属于高风险操作，需要重新认证，并原子更新全部受管 VLESS 入站；失败时保持旧身份可用并进入修复流程。

### 8.2 入站和路由

每个代理组分配一个未占用的 VLESS 端口，默认池为 `20000-20999`。端口分配前读取 3x-ui 当前入站和操作系统监听状态，发生冲突时选取下一个空闲端口，不能覆盖现有入站。

VLESS 入站标签只路由到该代理组的 Xray SOCKS 出站。禁止没有匹配规则时回落到 VPS 默认直连出口。

## 9. mixed 与 SOCKS5H 设计

### 9.1 认证

所有受管 mixed 入站复用一个全局用户名和密码。凭据按与 VLESS 身份相同的加密、重新认证、禁止日志和重置规则处理。

### 9.2 公网安全边界

SOCKS5 本身不加密。V1 要求：

- mixed 入站必须启用用户名和密码。
- 启用第一个 mixed 入站前，用户必须在 Gateway 高级设置中配置至少一个来源 IPv4 或 IPv6 CIDR。
- Xray 受管路由先允许白名单来源，再把该 mixed 入站的其他来源路由到受管 blackhole。
- 协议验证器使用带认证的回环连接；受管规则允许该固定回环验证路径，但不允许绕过 mixed 用户名和密码。
- 拒绝 `0.0.0.0/0` 和 `::/0` 作为 mixed 白名单。
- 白名单为空时 mixed 入站保持禁用，VLESS 不受影响。
- 页面明确提示 SOCKS5H 的 DNS 代理语义不等于传输加密。

mixed 端口默认池为 `30000-30999`，使用与 VLESS 相同的冲突检测和稳定分配规则。

### 9.3 DNS 语义

客户端使用 SOCKS5H 地址时把域名交给 mixed 入站。Xray 必须保留域名并转发到绑定的 AimiliVPN 本地 SOCKS 出站，由对应出口上下文完成解析。端到端验收必须包含 DNS 泄漏检查；不能只验证 IP 流量。

## 10. 页面和交互设计

### 10.1 主导航

主导航为：

1. 国家代理。
2. VLESS。
3. SOCKS5H。
4. 高级设置。
5. 账户安全。

服务状态压缩为顶部状态条，只显示 Gateway、AimiliVPN、3x-ui/Xray、活动代理组数量和需要处理的告警。

### 10.2 国家代理页

国家是第一层分类。每个国家卡片显示：

- 有效候选总数。
- 住宅候选数和当前活动代理组。
- 机房候选数和当前活动代理组。
- 当前实际出口 IP、延迟和最近验证时间。
- 启用、检测、换 IP、禁用和修复操作。

目录刷新只重新获取和验证候选节点，不创建、删除或更换已有代理组。

### 10.3 VLESS 与 SOCKS5H 页

两个页面均以国家为主分类，并支持住宅、机房和状态筛选。

每条活动记录显示：

- 国家和出口类型。
- 当前实际出口 IP。
- 入站端口和健康状态。
- AimiliVPN 槽位状态。
- Xray 路由状态。
- 最近端到端验证结果。

VLESS 页面提供单条复制、按国家复制和当前筛选结果 TXT 导出。SOCKS5H 页面提供相同功能，但只有来源白名单和 mixed 入站均有效时才允许复制。

连接信息默认遮罩。显示、复制和导出要求五分钟内完成过 Gateway 重新认证；响应使用 `Cache-Control: no-store`，前端不写入 Local Storage、Session Storage 或 IndexedDB。

### 10.4 检测与换 IP

- 重新检测：不改变端口、身份、节点或出口，只验证槽位、本地 SOCKS、Xray 配置、协议连通性、实际出口 IP 和 DNS。
- 更换 IP：只在同国家、同类型候选中选择另一个最近验证可用的节点，保持 VLESS/mixed 入口地址不变。
- 自动故障切换：当前节点失败时可在同国家、同类型内自动更换；没有合格候选时进入 `degraded`，禁止回退到其他国家、类型或 VPS 直连。

## 11. 高级设置和账户边界

### 11.1 Gateway 原生高级设置

AimiliVPN 和 3x-ui 的常用高级功能由 Gateway 自己渲染，继续使用同一个 Gateway 会话：

- AimiliVPN：有效节点、候选分类、节点检测、多出口槽位、容量、路由过滤和脱敏日志。
- 3x-ui：服务状态、受管入站、受管出站、受管路由、端口冲突、配置漂移和非受管资源只读摘要。
- 连接安全：mixed 来源白名单、全局 VLESS 身份重置、mixed 凭据重置和连接信息导出。

浏览器不直接调用 AimiliVPN 或 3x-ui 原生 API。

### 11.2 原生维护入口

- AimiliVPN 原生页面不作为常规公网入口，代码和功能保留，通过本机或 SSH 隧道维护。
- 原版 3x-ui 页面保留为专家维护入口，放在 Gateway 高级设置中，不嵌入 iframe。
- 原版 3x-ui 继续使用自己的账户、Cookie 和 TOTP。
- Gateway 账户与服务自动化凭据相互独立。

这实现的是“所有 Gateway 普通和高级页面使用一个账户”，不是覆盖原生页面的真正 SSO。相同密码、反向代理保护、自动填表或 Cookie 注入都不属于真正 SSO，本设计不采用这些方式。

## 12. 总体架构

    浏览器
      └─ Caddy / HTTPS
          └─ Aimili Gateway
              ├─ Gateway 认证、会话和重新认证
              ├─ 国家代理目录 API
              ├─ 代理组编排器
              ├─ 连接信息服务
              ├─ 协议验证器
              ├─ AimiliVPN Adapter
              └─ 3x-ui Adapter
                    │
                    ├─ 回环控制 API → AimiliVPN
                    └─ 回环管理 API → 3x-ui / Xray

Aimili Gateway、AimiliVPN、3x-ui、Xray 和 Caddy 继续是独立进程。Gateway 不获得任意 shell、systemd 或数据库写权限。

## 13. AimiliVPN 控制契约

AimiliVPN Fork 增加版本化、独立令牌认证、仅回环监听的控制 API，复用现有节点池、OpenVPN、策略路由和多出口函数，不复制隧道核心。

最小能力包括：

- 服务版本和能力协商。
- 有效候选列表及国家、节点类型、最近探测状态。
- 刷新节点池和查询任务状态。
- 创建、读取、启动、停止和删除槽位。
- 为单槽位设置国家和出口类型过滤。
- 在同国家、同类型内换节点。
- 查询槽位本地 SOCKS 端口。
- 通过槽位检测实际出口 IP、国家、类型、延迟和 DNS。

控制 API 不返回 OpenVPN 配置正文、原生网页账户、Cookie、随机路径或服务令牌。

活动代理组的最终分类必须使用槽位实测出口。如果候选分类与实测分类不一致，编排器拒绝该节点并继续选择其他候选。

## 14. 3x-ui 适配契约

3x-ui Adapter 通过受支持的本地管理 API：

- 探测版本、认证模式和能力。
- 读取入站、出站、路由和运行状态。
- 创建或更新受管 VLESS Reality 与 mixed 入站。
- 确保每个受管 VLESS 入站只有一个全局客户端身份。
- 创建或更新指向 AimiliVPN 槽位本地 SOCKS 端口的受管出站。
- 创建精确匹配受管入站标签的路由规则。
- 创建 mixed 来源白名单和默认拒绝规则。
- 重新读取并验证配置指纹。
- 安全删除当前代理组拥有且没有外部依赖的资源。

Adapter 不直接写 `x-ui.db`，不修改非受管资源，不保存 3x-ui TOTP 秘钥。未知 3x-ui 版本或认证能力不足时，写能力关闭，已有代理继续运行。

## 15. 跨服务编排

### 15.1 启用代理组

1. 验证 Gateway 会话、CSRF 和重新认证状态。
2. 读取最新目录、容量、端口和两个适配器能力。
3. 锁定 `国家 + 类型`，防止并发重复创建。
4. 预留 AimiliVPN 槽位和两个无冲突端口。
5. 选择最近验证可用的同国家、同类型候选。
6. 启动槽位并检测实际出口 IP、国家、类型和 DNS。
7. 创建受管 Xray SOCKS 出站。
8. 创建 VLESS 与 mixed 入站及精确路由。
9. 重新读取 AimiliVPN 与 3x-ui 状态和配置指纹。
10. 执行两种协议的端到端检测。
11. 全部通过后标记 `ready`；否则按反向顺序清理本次新建资源。

跨服务操作不是数据库事务。无法完整回滚时保存脱敏恢复状态并进入 `repair_required`，禁止用户重复点击造成更多写入。

### 15.2 换 IP

1. 保留稳定入站、端口、客户端身份、出站标签和路由。
2. 在同国家、同类型候选中排除当前节点和冷却节点。
3. 让 AimiliVPN 槽位切换节点。
4. 验证新的实际出口国家和类型。
5. 重新执行 VLESS、SOCKS5H 和 DNS 检测。
6. 成功后更新当前出口 IP；失败则尝试恢复旧节点，否则进入 `degraded`。

### 15.3 禁用代理组

禁用需要重新认证和明确确认。先停止新连接，再删除受管路由、入站、出站和槽位。任何非受管依赖都会阻止删除并显示脱敏冲突说明。

## 16. 协议验证器

运行时验证分为：

- AimiliVPN 槽位出口检测。
- Xray 配置和路由图检测。
- mixed SOCKS5H 实际请求与 DNS 检测。
- VLESS Reality 实际请求检测。

VLESS 检测使用固定路径的受控 Xray 客户端进程和临时最小配置：

- 只允许 Gateway 生成固定模板，不接受用户命令或任意 JSON。
- 客户端进程只连接 VPS 回环地址上的受管 VLESS 入站；实际外部请求由服务端 Xray 和 AimiliVPN 出口完成，因此不扩大 Gateway 现有的回环网络边界。
- 临时文件权限为当前服务用户独占，验证后立即删除。
- 连接秘密不出现在命令行、日志或错误响应中。
- 子进程有严格超时、输出大小限制和固定网络目标。
- 验证器以非 root 用户运行，不具有 systemd、Caddy 或文件系统管理权限。

完成声明必须以真实 VLESS 客户端和 SOCKS5H 客户端观察到预期出口 IP 为依据，不能只依据 3x-ui 返回成功。

## 17. Gateway 数据模型

SQLite 新增：

### 17.1 代理组

- 稳定标识、国家、出口类型、状态。
- AimiliVPN 槽位编号。
- VLESS 和 mixed 端口。
- 受管资源稳定标识。
- 当前出口 IP、配置指纹和验证时间。
- 最近错误类别和恢复状态。

### 17.2 加密连接凭据

- 全局 VLESS 客户端身份和 Reality 私密材料的密文。
- 全局 mixed 用户名和密码的密文。
- 密钥版本、创建时间和更新时间。

密文使用 Gateway 主密钥和独立用途上下文进行 AEAD 加密。数据库不保存对应明文。

### 17.3 操作与审计

- 编排操作类型、阶段、目标代理组、开始和完成时间。
- 成功、失败、回滚或需要修复状态。
- 只保存脱敏资源标识和错误类别。

候选节点完整 OpenVPN 配置、服务令牌、Cookie、UUID 明文、私钥、密码和完整连接 URI 不进入数据库或审计。

## 18. 浏览器 API

Gateway 提供版本化领域 API，不透传上游响应：

- 获取国家代理目录和筛选结果。
- 启动目录刷新并查询进度。
- 启用、读取、检测、换 IP、修复和禁用代理组。
- 获取高级设置的 AimiliVPN、3x-ui 和容量摘要。
- 管理 mixed 来源 CIDR。
- 在重新认证后显示、复制或导出连接信息。

写操作使用幂等键、资源版本和单代理组互斥锁。连接信息接口返回 `Cache-Control: no-store`，错误响应不包含上游正文或秘密字段。

V1 导出格式只有 UTF-8 TXT：

- VLESS：每行一个标准连接 URI。
- SOCKS5H：每行一个包含认证信息的 SOCKS5H URI。

不在 V1 增加 CSV、JSON、订阅聚合或云端同步。

## 19. 更新兼容性

- AimiliVPN 控制 API 使用版本和能力集合；缺少能力时只禁用受影响操作。
- 3x-ui Adapter 只对合同测试覆盖的版本开放写能力。
- 上游更新后先重新探测，再对受管资源做只读指纹检查。
- 未知版本进入只读状态，现有 Xray 和 AimiliVPN 进程继续运行。
- Gateway 不自动升级 AimiliVPN、3x-ui、Xray、Caddy 或操作系统。
- 原版 3x-ui 专家入口和 AimiliVPN 本地维护入口始终保留为恢复路径。

## 20. 错误处理和安全降级

- AimiliVPN 不可用：目录和代理组显示不可用，3x-ui 与 Gateway 登录不受影响。
- 3x-ui 不可用：不修改 AimiliVPN 槽位，已有槽位可继续运行，连接配置写操作关闭。
- 候选不足：代理组保持 `degraded`，不跨国家或类型回退。
- 容量不足：拒绝启用并显示当前活动组和上限。
- 端口冲突：重新分配空闲端口；没有空闲端口时不写入上游。
- 配置漂移：停止自动修复，要求用户明确选择。
- 部分失败：保存恢复状态，只允许“继续修复”或“回滚本次受管资源”。
- Gateway 停止：已有 AimiliVPN、Xray 入站、路由和代理流量继续运行。

## 21. 测试和验收

### 21.1 自动测试

- 国家和出口类型归类。
- 全量目录与活动容量分离。
- 一个国家和类型只能有一个代理组。
- 端口分配和冲突处理。
- 全局 VLESS 身份在所有受管入站中一致。
- 每个 VLESS 入站只有一个客户端。
- mixed 认证、来源白名单和默认拒绝。
- 受管资源命名空间和非受管资源保护。
- 启用、换 IP、禁用、回滚和部分失败状态机。
- API 重新认证、CSRF、幂等和并发锁。
- 连接信息禁止缓存、禁止日志和审计脱敏。
- 未知上游版本安全降级。

### 21.2 隔离端到端验收

在非生产环境建立至少两个不同国家或类型的测试代理组：

1. 刷新目录并显示所有有效国家和候选。
2. 启用一个住宅或机房代理组。
3. 验证 3x-ui 只新增 `agw-` 资源，原有资源未变化。
4. 验证 VLESS 和 mixed 使用同一 AimiliVPN 槽位。
5. 通过真实 VLESS 客户端访问外部检测服务，出口 IP 与 Gateway 页面一致。
6. 通过真实 SOCKS5H 客户端访问 IP 与 DNS 检测服务，出口 IP 一致且没有本地 DNS 泄漏。
7. 换 IP 后两个入口地址不变，出口 IP 更新且国家、类型不变。
8. 模拟 AimiliVPN、3x-ui、候选失效和跨服务部分失败。
9. 确认未授权来源不能使用 mixed。
10. 确认日志、SQLite、进程参数和浏览器持久存储不含连接秘密。

### 21.3 生产验收

生产部署必须另行取得授权，并按以下顺序：

1. 刷新 VPS、3x-ui、Xray、AimiliVPN、Caddy、端口和容量只读基线。
2. 备份 3x-ui/Xray 配置、AimiliVPN 数据和 Gateway SQLite。
3. 先只启用一个代理组。
4. 使用用户实际客户端完成 VLESS 与 SOCKS5H 原路径测试。
5. 观察内存、CPU、进程、隧道和流量稳定性。
6. 在验证证据支持下逐个增加代理组，最多达到初始上限 4。
7. 每次增加后重新验证全部已有代理组。

局部 API 成功、入站存在、槽位显示 `up` 或单独出口检测通过，都不能代替完整用户路径验收。

## 22. 修订后的交付顺序

V1-A 已完成，后续重新拆分为三个纵向里程碑：

1. **V1-B 单代理组闭环**：版本化 AimiliVPN 控制 API、3x-ui 受管资源适配、一个国家和类型的 VLESS＋mixed 创建、真实出口验证和回滚。
2. **V1-C 国家目录与多组管理**：全量目录、分类、容量上限、最多四个活动组、检测、换 IP、自动故障切换和状态机。
3. **V1-D 产品页面与高级设置**：国家、VLESS、SOCKS5H 页面，复制和 TXT 导出，AimiliVPN/3x-ui 高级设置、安全重置和完整生产验收。

每个里程碑都必须通过自动测试和隔离端到端验收。旧的 V1-B AimiliVPN 独立管理计划和旧的 V1-C 通用 3x-ui 绑定计划不得继续执行；本设计批准后为上述三个里程碑编写新的实施计划。

## 23. 最终验收标准

后续 V1 完成必须同时满足：

1. 首页以国家代理为核心，不再以三张服务状态卡为主体。
2. 目录展示 AimiliVPN 当前有效池中的全部已验证国家和候选 IP。
3. 用户可在容量范围内启用国家＋住宅/机房代理组。
4. 每个活动组只有一个稳定 VLESS 入站、一个稳定 mixed 入站和一个 AimiliVPN 出口槽位。
5. 所有 VLESS 入站复用一个客户端身份，每个入站在 3x-ui 中只有一个客户端。
6. VLESS 和 SOCKS5H 真实流量均经过页面标示的出口 IP。
7. SOCKS5H 域名解析经过代理出口，未授权来源被拒绝。
8. 检测不换 IP；换 IP 不改变入口地址，并保持国家和类型。
9. 复制和导出按国家、协议和类型筛选，秘密默认遮罩且不被持久化到浏览器。
10. Gateway 普通页面和高级设置使用同一个 Gateway 账户。
11. 原版 3x-ui 专家页面仍独立登录，未把相同密码或反向代理描述为 SSO。
12. 非受管 3x-ui/Xray 资源没有被接管、覆盖或删除。
13. Gateway、AimiliVPN、3x-ui、Xray 和 Caddy 继续独立运行和更新。
14. 所有完成结论具有最新自动测试、隔离端到端和用户原路径验证证据。
