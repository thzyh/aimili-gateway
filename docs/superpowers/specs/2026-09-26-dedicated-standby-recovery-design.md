# 专属备用与持续故障恢复设计

## 目标

将主连接和普通出口统一为住宅优先、机房兜底的持续恢复模型。测试基线为 4 个活动连接（主连接 + 3 个普通出口）和 4 个一一对应的专属备用连接。故障时优先提升已经通过真实出网检测的专属备用，后台继续补充备用；当前国家无合格节点时，按可用质量指标选择其他国家。暂不接入外部 IP 质量网站，所有 IP 质量统计显示为未启用。

## 边界

- 只修改 `aimili-gateway`；不修改独立客户端仓库。
- 不新增 ping0.cc 依赖，不把网页抓取结果当作 IP 合格依据。
- 不采用无边界的快速重试；使用候选冷却、退避、并发限制和最终人工状态。
- 活动连接数量和备用数量受实时 VPS 容量保护。目标配置为 4+4，但资源不足时拒绝新增，不影响已有连接。
- 不记录密码、UUID、私钥、完整订阅链接或 OpenVPN 配置内容。

## 运行模型

每个未暂停的活动连接有一个保护目标：`main`、`slot:N`。专属备用不再配置固定候选国家，候选范围由保护目标当前国家和全局节点池计算；暂停槽位保留配置但不创建常驻热备用。备用状态包括 disabled、provisioning、checking、ready、promoting、degraded、waiting_manual。

故障流程：

1. 连续健康检查失败达到可配置确认次数。
2. 提升对应 ready 备用；提升前再次确认隧道、路由和实际出口。
3. 后台为该保护目标补充新的备用，不阻塞其他出口。
4. 候选排序先使用故障节点原国家，再使用节点池中综合可用性最高的国家；每个国家内部住宅优先、机房兜底。
5. 每个候选单轮只拨号一次，失败进入冷却；循环使用指数退避。达到恢复时间预算后进入人工状态，后续周期仍可由管理员重新触发。

主连接和普通出口共用同一候选选择、验证和日志接口。

## 国家统计

候选国家 API 增加以下字段：

- `dialableCount`：通过基础配置检查且允许拨号的节点数。
- `freshEgressCount`：在新鲜度窗口内通过真实出口检测的节点数。
- `ipQualityPassCount`：当前为 `null`，因为 IP 质量检测暂未实现。
- `ipQualityStatus`：固定返回 `not_implemented`。
- `residentialCount`、`datacenterCount`、`checkedAt`。

国家排序使用当前故障国家优先，然后按 `dialableCount`、`freshEgressCount`、住宅数量和平均检测延迟排序。活动节点、备用节点、重复出口 IP 和冷却节点不计入可分配数量。

## 高级设置

高级设置增加“故障恢复策略”区域，读取并修改以下持久化参数：故障确认次数、活动健康检测间隔、备用检测间隔、单候选拨号超时、单轮候选上限、最大并发拨号数、首次重试间隔、最大重试间隔、节点冷却时间、单次恢复时间预算、是否允许跨国家兜底、是否允许机房兜底。活动目标数和备用目标数由当前未暂停出口实时推导，不允许手工填入相互矛盾的数量。

服务端按照实时内存、CPU、负载、监听端口和现有进程计算上限；前端显示当前值、自动上限、已占用数量和拒绝原因。IP 质量列显示“暂未启用”，不显示伪造的 0 或通过数量。

## 日志与可观测性

每个恢复事务输出结构化事件：目标、旧节点摘要、候选节点摘要、国家、IP 类型、拨号、TUN、路由、出口检测、IP 质量状态、拒绝原因、轮次、退避时间、耗时和最终状态。候选 IP 仅保存脱敏摘要。前端显示最近恢复事务、当前候选阶段、备用状态和人工处理原因。

## 验收标准

- 4 个活动连接能稳定维持 4 个专属备用，资源不足时安全拒绝扩容。
- 主连接和普通出口使用同一替换逻辑。
- 住宅候选通过验证时不会先选机房；住宅全部不合格时才允许同国机房兜底。
- 当前国家无合格候选时能按国家统计选择其他国家，并显示跨国原因。
- 备用提升不影响其他活动出口，提升后能后台补齐备用。
- 退避、冷却、恢复时间预算和人工状态可配置且重启后保留。
- 国家统计和高级设置 API、前端显示、日志字段一致。
- IP 质量检测明确显示未启用，不阻止其他恢复流程。
- 本地定向测试、前端测试和构建通过；bj 4+4 阶梯验证记录内存、CPU、磁盘、OpenVPN、Gateway、Xray 和 Caddy 状态。
