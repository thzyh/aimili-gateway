# Test 风格 VLESS 订阅与统一控制台 V1 修订设计

日期：2026-08-29  
状态：已批准、已实现并完成生产验收

## 1. 修订背景

上一版把“复制单地址聚合入口”定义为 Xray 服务端 balancer：客户端得到一个 VLESS 入口，服务器再在多个 SOCKS 出口之间选择。经过实际使用 3x-ui 手动创建的 `test` 客户端后，确认用户真正需要的是 3x-ui 原生订阅效果：一个客户端订阅链接，导入 v2rayN 后得到多个独立 VLESS 节点。

本修订取消“单地址 balancer 入口”作为统一控制台的主要复制功能，改为由 3x-ui 原生生成一个多入站 VLESS 订阅。每个 VLESS 入站仍保持独立监听和独立 AimiliVPN 出口，底层 AimiliVPN、3x-ui 和 Gateway 仍然是三个独立服务。

## 2. 设计时确认的生产事实

2026-08-29 对 `ssh ny` 上的 3x-ui 数据库和 Xray 路由进行了只读核对：

- 手动 `test` 客户端关联了 `8443`、`20000`、`20001`、`20002` 四个 VLESS 入站；同一个客户端身份在四个入站中复用。
- `test` 没有关联 mixed 入站，因此订阅内容是多个 VLESS 节点，不是 SOCKS5H 地址。
- Gateway 的 `aimili-gateway-aggregate` 客户端只关联 `21000` 聚合 VLESS 入站。
- `21000` 当前经过 `agw-aggregate` balancer 和 observatory 选择多个 SOCKS 出口。
- 当前受管 Reality 入站的 ML-DSA Seed/Verify 仍为空。

上述事实只用于设计依据；文档不记录 UUID、密码、Cookie、私钥或完整订阅链接。

## 3. V1 目标和非目标

### 3.1 目标

1. 在 Gateway 页面提供“复制 VLESS 订阅”按钮，效果与 3x-ui 的 `test` 订阅一致。
2. 一个 Gateway 订阅客户端关联所有需要向用户公开的 VLESS 入站：主连接 `8443` 和当前启用的 Gateway 受管 VLESS 入站。
3. 每个订阅条目仍是独立节点，保留国家、住宅/机房分类、独立端口和独立出口。
4. 保留 SOCKS5H 代理池的单地址复制、批量复制和导出功能。
5. 保留主连接真实检测、固定出口位标志、候选节点“替换到出口位”以及失败回滚设计。
6. 继续保留 3x-ui 专家模式和 AimiliVPN 专家页面，不重写 Xray 或 3x-ui 核心。

### 3.2 非目标

- 不再把 `21000` balancer 作为主要的“复制单地址聚合入口”。
- 不把多个 VLESS 入站合并成一个监听端口。
- 不把 mixed/SOCKS5H 塞进 v2rayN VLESS 订阅。
- 不把 Python AimiliVPN 和 Go Gateway 合并成一个进程。
- 不进行服务器全面改造或多租户设计。

## 4. 方案选择

### 方案 A：3x-ui 原生多入站订阅（推荐）

Gateway 创建或维护一个专用订阅客户端，例如 `aimili-gateway-subscription`，通过 3x-ui 的客户端关联机制将其关联到 `8443` 和所有当前启用的 Gateway VLESS 入站。Gateway 从 3x-ui 的订阅配置生成或读取该客户端的订阅地址，页面只负责复制和导出。

优点：

- 与用户已经验证成功的 `test` 工作方式一致；
- v2rayN、Clash 等客户端继续使用 3x-ui 原生订阅格式；
- 不需要额外监听端口；
- 每个出口仍然相互独立，故障不会改变其他节点。

代价：

- Gateway 需要维护一个跨入站的订阅客户端关联；
- 3x-ui API 版本变化时需要适配器兼容测试。

### 方案 B：Gateway 自己生成订阅文本

Gateway 读取各 VLESS 入站的公开连接参数，自己拼接 Base64 或 JSON 订阅。

优点是可以完全控制输出；缺点是会重复实现 3x-ui 的订阅格式、客户端兼容性和路径规则，容易与 3x-ui 更新不一致。不采用。

### 方案 C：保留 balancer，同时新增订阅

同时保留 `21000` 单入口和 `test` 风格多节点订阅。

这种方案兼容性最高，但会继续维护一套用户不再需要的聚合入站、客户端和 balancer，增加 512 MiB VPS 的配置复杂度和历史残留。不作为 V1 默认方案；如迁移时发现外部仍在使用 `21000`，可短期兼容保留。

## 5. 推荐架构

采用方案 A，并把按钮名称改为：

```text
复制 VLESS 订阅
```

不再使用“复制单地址聚合入口”这个名称。

### 5.1 订阅客户端边界

- 客户端名称推荐为 `aimili-gateway-subscription`，避免与用户手动创建的 `test` 混淆。
- 该客户端只有一个订阅身份和一个订阅 ID。
- 关联对象仅包括 VLESS 入站：
  - 非受管主连接 `aimili-reality`（端口 `8443`）；
  - 当前启用且归 Gateway 所有的 `agw-*-vless` 入站。
- mixed 入站不加入该订阅。
- 非受管客户端、非受管入站和用户手动创建的 `test` 不由 Gateway 删除或改写。

### 5.2 订阅内容更新

每次 reconcile、启用/停用出口位、候选节点替换和主连接修复后，Gateway 重新核对订阅客户端关联：

- 新启用的 Gateway VLESS 入站加入订阅；
- 被停用或删除的 Gateway VLESS 入站从订阅移除；
- `8443` 只有在精确核对仍是原主连接 Reality 入站后才保留；
- 关联变更不改变入站端口、Reality 密钥、客户端 UUID 或 Xray 路由。

### 5.3 旧聚合资源迁移

`agw-aggregate-vless`、`21000` 和 `agw-aggregate` balancer 属于上一版 Gateway 受管资源。迁移采用以下顺序：

1. 备份 3x-ui 数据库和当前 Xray 配置；
2. 创建并验证新的订阅客户端；
3. 通过 3x-ui 订阅接口确认订阅返回多个 VLESS 条目；
4. 通过 v2rayN 或等价 Xray 客户端验证至少一个订阅条目可用；
5. 确认 `21000` 没有被 Gateway 外部流程依赖后，再删除旧聚合入站、客户端和 balancer 配置；
6. 删除失败时保留旧资源并进入修复状态，不影响现有节点。

旧聚合资源不会依据名称直接删除，必须满足 Gateway 所有权、备份成功和订阅验证成功三个条件。

## 6. 统一控制台功能调整

### 6.1 VLESS 节点池

- 顶部按钮改为“复制 VLESS 订阅”。
- 该按钮复制一个 3x-ui 风格订阅地址，而不是复制 `21000` 的单个 VLESS URI。
- “复制节点列表”和“导出”继续输出当前筛选条件下的独立 VLESS 地址。
- 页面明确显示：订阅包含多个独立节点，不是服务端自动选择出口的单入口。

### 6.2 SOCKS5H 代理池

保持现有设计：每个已验证出口复制一个 `socks5h` 地址，支持批量复制和导出，不加入 VLESS 订阅。

### 6.3 固定出口位和候选替换

保留上一版修订：

- 已启用节点显示稳定的“出口位 1、出口位 2……”标志；
- 固定显示开关默认开启，已启用节点不受普通筛选影响；
- 已启用节点不显示“换 IP”；
- 未启用候选改为“替换到出口位”，通过下拉框选择目标槽位；
- 替换过程保留原端口、入站和客户端，切换 AimiliVPN 节点后重新检测；
- 失败自动恢复原节点，恢复失败才标记 `repair_required`；
- 替换弹窗提供取消和关闭操作。

## 7. 主连接检测

`agw-main` 使用独立的检测流程，不调用普通槽位轮换：

1. 读取 AimiliVPN 主连接状态；
2. 通过主连接 mixed 入口实测 SOCKS5H；
3. 通过 `8443` 实测 VLESS Reality；
4. 记录两种协议延迟、出口 IP、检测时间和错误码；
5. 页面显示真实延迟和“检测”按钮。

主连接仍然加入 VLESS 订阅，但不显示“替换到出口位”。

## 8. Reality 与 ML-DSA-65

- Reality target/SNI 继续使用已经实测稳定的本机 Caddy 目标，不直接切换到外部 Amazon 模板。
- ML-DSA-65 采用能力检测后启用：只有 Xray、3x-ui 和客户端导出链路均确认支持时才启用。
- 生成的 Seed 只存放在受限服务端配置中，不显示在页面或日志。
- Verify 只作为客户端公开配置的一部分；如果 VLESS URI 标准无法表达，则导出受支持的 JSON 配置。
- 握手验证失败时自动回退到 X25519，并保留诊断记录。

## 9. API 与适配器变更

### 9.1 订阅接口

增加受认证的 Gateway API：

```text
GET /api/v1/proxy-groups/subscription
```

响应只在用户主动复制/导出时返回订阅地址；服务端日志、错误响应和审计记录不得记录完整地址。订阅地址在前端内存中使用，不写入 localStorage、数据库或埋点。

原 `/api/v1/proxy-groups/aggregate/connections` 在迁移期返回明确的弃用错误或兼容跳转，不再生成 `21000` 地址。

### 9.2 3x-ui 适配器

新增以下逻辑，具体 HTTP 路径以当前 3x-ui API 实测为准：

- 查找或创建专用订阅客户端；
- 维护客户端与多个 VLESS 入站的关联；
- 读取订阅路径和订阅 ID；
- 验证订阅返回的入站数量和端口集合；
- 删除旧聚合资源前执行所有权和引用检查。

浏览器不能提交任意 Xray JSON；Reality 和客户端字段继续由服务端模板控制。

### 9.3 AimiliVPN 适配器

继续增加正式的：

```text
POST /control/v1/slots/{slot}/assign
```

用于将候选节点装载到指定出口位，并提供原节点回滚能力。该接口与订阅改造相互独立。

## 10. 数据模型

新增或扩展 Gateway 数据：

- 订阅客户端资源名、3x-ui 客户端引用、订阅路径元数据；
- 主连接 candidate/VLESS/SOCKS5H 延迟、检测时间和错误码；
- 受管出口位编号和固定显示元数据。

不保存完整订阅地址、客户端密码、UUID、Cookie 或 Reality 私钥。

## 11. 错误处理与回滚

- 订阅客户端创建成功但关联失败：回滚新增客户端或标记 `repair_required`，不删除现有出口。
- 订阅验证返回数量不符：停止清理旧聚合资源，保留当前配置。
- 某个节点替换失败：恢复原 AimiliVPN 节点和出口位元数据。
- 3x-ui 更新导致订阅 API 不兼容：Gateway 进入只读兼容模式，VLESS/SOCKS5H 现有地址不主动改写。
- 任何 Xray 配置更新后都必须验证 `x-ui`、现有独立 VLESS、主连接 `8443` 和 SOCKS5H。

## 12. 测试计划

### 本地测试

- 3x-ui 适配器：订阅客户端创建、关联、幂等 reconcile、漂移检测和回滚。
- API：订阅地址只在认证请求中返回，错误和日志不泄露敏感字段。
- 前端：按钮改名、复制/导出、固定节点、替换弹窗取消和错误显示。
- Orchestrator：主连接检测、候选替换、失败回滚和旧聚合资源保护。
- ML-DSA 能力检测和 X25519 回退。

### VPS 阶梯验证

1. 只读审计现有 3x-ui 资源和数据库备份；
2. 创建订阅客户端并验证多个 VLESS 条目；
3. v2rayN 导入订阅，确认可见多个节点且至少一个节点真实连通；
4. 验证 Gateway 页面复制订阅、独立 VLESS、SOCKS5H 和主连接检测；
5. 最后再评估删除 `21000` 旧聚合资源；
6. 任一阶段失败立即恢复备份，不尝试无证据的外部 Reality 目标替换。

## 13. 验收标准

- Gateway 页面按钮名称为“复制 VLESS 订阅”。
- 复制结果是一个 3x-ui 风格订阅地址，导入 v2rayN 后出现多个独立 VLESS 节点。
- 节点数量与当前主连接及启用的 Gateway VLESS 入站一致。
- mixed/SOCKS5H 不出现在 VLESS 订阅中。
- 每个独立节点仍按自身入站路由到对应 AimiliVPN 出口。
- 主连接显示真实 VLESS/SOCKS5H 检测延迟。
- 未启用候选可以选择目标出口位替换，启用节点不再出现“换 IP”。
- 旧聚合资源只有在完成备份、订阅验证和无引用检查后才允许清理。
- 不输出或持久化密码、Cookie、UUID、私钥和完整订阅链接。
