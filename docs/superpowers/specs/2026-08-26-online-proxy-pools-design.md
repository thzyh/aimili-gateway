# Aimili Gateway 在线代理池 V1-C 设计

## 1. 状态与决策

本设计取代 `2026-08-25-country-proxy-console-design.md` 中“国家大卡片、按国家和类型启用有限代理组”的产品界面与资源身份设计。已确认采用方案一：AimiliVPN 当前有效池中的每个唯一出口都建立独立槽位，并由 3x-ui/Xray 提供一条 VLESS Reality 地址和一条 SOCKS5H 地址。

本阶段仍保留 AimiliVPN、Gateway、3x-ui/Xray 三个独立服务，不重写 Xray 或 3x-ui 核心，不把 Python 与 Go 合并为单进程，也不扩展为多租户或服务器全面改造。

## 2. 第一版用户体验

统一控制台主导航只保留“VPN 节点池”“SOCKS5H 代理池”“高级设置”和账户菜单。首页删除 Aimili Gateway、AimiliVPN、3x-ui 三张服务状态卡，不再按国家铺设大卡片。

两个资源池使用同一份在线出口数据。页面使用紧凑表格，提供国家、IP 类型、状态和延迟排序；每行显示国家、住宅或机房、实际出口 IP、协议实测延迟、状态和最近检测时间。

- VPN 节点池支持单条复制 VLESS URI，以及导出当前筛选结果为 UTF-8 TXT。
- SOCKS5H 代理池支持单条复制标准 SOCKS5H URI，以及导出当前筛选结果。
- 完整地址默认不在页面铺开，不进入浏览器持久存储。
- 检测、换 IP 和故障信息属于行级次要操作，放入操作菜单或详情抽屉。

视觉参考只吸收开源项目的信息架构原则：CoreUI 的后台密度、Shadcn Vue Admin 的克制组件和可访问性、TailAdmin 的响应式工具栏。实现继续使用项目现有 Vue 3、Vite 和原生 CSS，不新增 UI 框架。

## 3. 在线池语义

候选可用不等于代理可用。记录只有依次通过以下检查后才进入 `ready`：

1. 指定 AimiliVPN 候选已建立独立 OpenVPN/TUN 槽位。
2. 本地 SOCKS 出口能够访问外部检测服务。
3. 实际出口 IP、国家和住宅/机房分类已经确认。
4. VLESS Reality 真实代理流量成功。
5. SOCKS5H 真实代理流量和代理 DNS 成功。
6. 两种协议观察到相同的预期出口 IP。

主列表可以显示正在创建或故障的目标记录，但只有 `ready` 记录允许复制和导出。验收时所有 AimiliVPN 当前有效候选对应的唯一实际出口必须进入 `ready`；容量等待不算完成。

## 4. 资源模型

`ProxyGroup` 从“国家＋类型”的唯一资源升级为“候选出口实例”。稳定资源名使用国家、类型和候选 ID 的短哈希，避免同国家同类型冲突，也不把原始候选标识直接暴露为公网信息。

每个出口实例保存候选 ID、国家、类型、候选地址、实际出口 IP、AimiliVPN 槽位、本地 SOCKS 端口、VLESS/mixed 端口、受管资源 ID、Reality 公共连接材料、配置指纹、候选延迟、VLESS 实测延迟、SOCKS5H 实测延迟、状态和检测时间。

同一实际出口 IP 若由多个候选产生，只保留延迟更低且稳定的一个实例，冗余槽位在新实例验证完成后回收。

## 5. AimiliVPN 控制契约

控制 API 保持回环监听和 Bearer token 认证，扩展版本化契约：

- `GET /control/v1/candidates` 返回安全候选快照。
- `GET /control/v1/slots` 返回受管槽位安全快照，用于重启恢复和漂移核对。
- `POST /control/v1/slots` 接受 `candidateId`，并校验候选仍可用、国家和类型一致。
- 现有单槽位读取、检测、换 IP 和删除接口继续兼容。

指定候选创建复用 AimiliVPN 已有的节点锁定和槽位分配能力。API 不返回 OpenVPN 配置正文、token、Cookie 或其他秘密。

## 6. 3x-ui/Xray 受管资源

每个在线出口创建一个指向 AimiliVPN 回环 SOCKS 端口的 Xray 出站、一个独立端口的 VLESS Reality 入站、一个独立端口的 mixed 入站，以及对应的精确路由和 mixed 默认拒绝规则。

所有 VLESS 入站复用一个全局客户端 UUID，每个入站只包含这一个客户端。所有 mixed 入站复用一个全局用户名和密码，但仍必须受来源 CIDR 限制。

Adapter 不直接写 `x-ui.db`，只操作 `agw-` 命名空间及匹配所有权指纹的资源，不修改专家模式中的非受管资源。

## 7. 协调与恢复

Gateway 增加后台协调器。目录刷新只更新候选快照并触发异步协调，不在一个浏览器请求内串行等待全部出口建立。

协调顺序为：发现目标候选、创建记录、指定候选槽位、等待真实出口、创建 3x-ui 资源、执行双协议验证、标记 `ready`。任一步失败按反向顺序回收本次新建资源，并保存脱敏错误类别。

已有 `ready` 出口不会因一次候选快照缺失立即拆除。只有真实链路连续失败或超过缺失宽限期才回收。重启后先核对数据库、AimiliVPN 槽位和 3x-ui 资源，再继续缺失步骤。

## 8. 浏览器 API

Gateway 提供资源池查询和筛选元数据、异步刷新、单出口检测和换 IP、近期重新认证后的连接读取与筛选结果导出。连接和导出响应使用 `Cache-Control: no-store`；写操作继续使用 CSRF、幂等键、资源版本和互斥锁；错误响应不包含上游正文和秘密字段。

## 9. 账户与安全边界

节点池、代理池和 Gateway 原生高级设置使用 Gateway 账户。AimiliVPN 由 Gateway 通过内部自动化凭据调用。原版 3x-ui 专家模式继续要求 3x-ui 登录；相同密码或反向代理保护不称为真正 SSO。

第一次显示、复制或导出秘密前要求重新认证；短时窗口内不重复打断。VLESS UUID、mixed 凭据和 Reality 私密材料继续加密存储，不写日志或审计。mixed 白名单拒绝 `0.0.0.0/0` 和 `::/0`。

## 10. 容量与部署门槛

当前 Gateway 默认 1 组、代码上限 4；AimiliVPN 有效池目标 30、槽位上限 16。V1-C 将配置上限扩展到 64，但生产值必须根据压测逐级提升。

纽约 512MB VPS 按 `1 → 4 → 8 → 12 → 16 → 更高数量` 阶梯部署。每级检查总内存、交换空间、OOM、CPU、进程、文件描述符、TUN、策略路由，以及全部已有 VLESS、SOCKS5H 和 DNS 链路。任一级失败停止扩容并保留上一级稳定值。

若硬件无法让全部有效候选在线，不能宣称 A 完成。必须明确报告需要升级 VPS 或降低 AimiliVPN 有效池规模，不静默改成按需启用。

## 11. 更新兼容性

AimiliVPN 和 3x-ui 继续独立更新。Adapter 在写操作前探测版本和能力；未知版本进入只读安全降级，已有代理继续运行。部署固定到已验证提交，升级后先运行契约测试和所有权指纹核对，再恢复协调。

## 12. 验收标准

- 三张服务状态卡消失，两个资源池成为主界面。
- 国家和 IP 类型使用下拉筛选，页面为紧凑表格。
- 每个唯一可用出口都有独立在线槽位、VLESS 和 SOCKS5H 地址。
- VLESS 入站均只有同一个全局客户端。
- 两种协议实际出口与页面一致，SOCKS5H DNS 不泄漏。
- 显示协议实测延迟和检测时间，候选延迟不冒充完整链路延迟。
- 单条复制、筛选导出、秘密遮罩和重新认证正确。
- 未授权 mixed 来源被拒绝。
- 服务重启后资源能够核对和恢复。
- 非受管 3x-ui/Xray 资源保持不变。
- 生产容量结论有最新阶梯压测和用户路径端到端证据。
