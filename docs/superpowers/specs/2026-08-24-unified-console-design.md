# AimiliVPN + 3x-ui 统一控制台 V1 设计

## 1. 文档状态

- 日期：2026-08-24
- 项目：`aimili-gateway`
- 阶段：正式设计，等待用户第二次审核
- 适用范围：个人单管理员使用

本文定义 AimiliVPN 与 3x-ui 统一控制台第一版的需求、架构、认证边界、适配方式、更新兼容性、安全模型和验收标准。本文批准前不编写实施计划，不开始业务代码或生产部署。

## 2. 背景与事实基线

本设计基于以下本地事实：

1. `aimili-vpngate` 当前由用户 Fork 的 `custom` 分支维护，已有节点池、路由、多出口和管理网页能力。
2. AimiliVPN 已有供原网页使用的管理接口，但接口未版本化，也没有能力协商端点。
3. `aimili-3xui-simple-deploy` 当前不是 Git 仓库，部署脚本固定 AimiliVPN 的已验证提交，并在首次安装时固定 3x-ui 版本；对已有 3x-ui 会保留用户在原后台完成的升级。
4. 现有部署脚本已经通过 3x-ui 的本地 Web 管理 API 完成登录、设置、Xray 配置和入站操作，没有直接写入 3x-ui 数据库。
5. 原版 3x-ui 管理页面、AimiliVPN 管理页面和订阅入口目前由 Caddy 反向代理；底层管理服务监听回环地址。
6. 本地没有 3x-ui 源码，生产 VPS 的当前运行版本和实时状态没有在本次设计阶段刷新。

因此，V1 可以复用现有管理能力，但必须在统一控制台与上游接口之间建立版本化适配层，不能让浏览器直接依赖底层服务的内部 API。

## 3. 目标

V1 的目标是尽快交付一个可运行、可验证的个人统一控制台：

1. 用户日常只登录一次统一控制台，即可完成 AimiliVPN 和 3x-ui 的常用操作。
2. AimiliVPN、3x-ui 和 Xray 继续独立运行、更新和排障。
3. 原版 3x-ui 后台保留为专家模式，复杂功能仍由上游页面提供。
4. 统一控制台通过适配器调用两个服务，不直接耦合其数据库或前端实现。
5. 上游版本不兼容时安全降级，禁止危险写操作，同时保留专家模式恢复路径。
6. 所有写操作在返回成功前重新读取真实状态进行验证。

## 4. 非目标

V1 明确不包含：

- 多租户、组织、团队、成员邀请、租户隔离和计费。
- 复杂 RBAC；V1 只有一个本地管理员身份。
- 覆盖原版 3x-ui 页面的真正单点登录。
- 重写 Xray、3x-ui 或 AimiliVPN 核心。
- 删除或裁剪 3x-ui 上游功能源码。
- 把 Python AimiliVPN、Go 3x-ui、Xray 与控制台合并为单个进程。
- 任意 Xray JSON 编辑器、全部传输协议向导或 3x-ui 系统设置镜像。
- 一键升级 AimiliVPN、3x-ui、Xray、Caddy 或操作系统。
- 服务器防火墙、SSH、内核、证书和网络架构的全面改造。
- 未经新的明确授权连接或修改生产 VPS。

## 5. 用户与核心流程

### 5.1 用户模型

V1 只支持一个个人管理员账户。系统不设计租户字段、组织表、角色继承或资源归属模型。审计记录中的操作者固定为该管理员身份，但仍保留会话标识，便于追踪浏览器会话。

未来如确需多人使用，应作为独立版本重新设计账户、授权和审计模型，不能在 V1 中预埋半成品多租户逻辑。

### 5.2 日常流程

1. 用户打开统一控制台并完成控制台自身登录。
2. 首页同时显示 AimiliVPN、3x-ui/Xray 和适配器状态。
3. 用户管理 VPN 节点、路由模式和多出口槽位。
4. 用户查看 3x-ui 入站和客户端，完成常见启停、配额和到期时间调整。
5. 用户将某个入站绑定到 AimiliVPN 主出口或指定多出口槽位。
6. 遇到高级配置或适配器不兼容时，用户打开专家模式并使用 3x-ui 自身账户登录。

### 5.3 成功标准

个人用户无需日常往返两个原生后台，即可完成节点选择、出口管理、入站和客户端管理以及入站到出口的绑定；复杂功能仍有原版 3x-ui 后台可用。

### 5.4 先跑起来的交付顺序

V1 按三个可独立运行和验收的纵向增量交付，不能等全部功能完成后才首次启动：

1. **V1-A 可运行控制台**：完成单管理员初始化、密码与 TOTP 登录、Caddy 入口、两个适配器的只读探测、统一状态页和专家模式链接。该增量不修改底层业务配置。
2. **V1-B AimiliVPN 日常管理**：增加版本化 AimiliVPN 控制 API，完成节点、路由和多出口常用操作以及写后验证。
3. **V1-C 3x-ui 管理与出口绑定**：完成受支持版本上的入站、客户端和跨服务出口绑定，并验证真实流量出口。

每个增量都必须能够独立构建、启动、测试和回滚。V1-A 验收后即可作为只读统一入口使用；后续增量在同一架构上补充能力，不推翻已运行的认证、前端入口或适配器契约。

## 6. 总体架构

采用“模块化统一控制台＋两个独立服务＋专家模式”方案：

```text
浏览器
  └─ Caddy / HTTPS
      ├─ /api/v1/* ────────────────┐
      ├─ 统一控制台静态页面         │
      │                             ▼
      │                    Aimili Gateway
      │                    ├─ 认证与会话
      │                    ├─ 业务 API
      │                    ├─ 审计与兼容性
      │                    ├─ AimiliVPN Adapter
      │                    └─ 3x-ui Adapter
      │                           │
      │                仅回环地址上的服务调用
      │                    ┌──────┴──────┐
      │                    ▼             ▼
      │                AimiliVPN       3x-ui / Xray
      │
      ├─ 既有专家模式入口 ───────────→ 原版 3x-ui 页面
      └─ 既有订阅入口 ───────────────→ 3x-ui 订阅服务
```

### 6.1 部署单元

生产环境新增一个 `aimili-gateway` systemd 服务：

- 默认监听 `127.0.0.1:9080`，允许通过配置修改。
- 以无登录权限的专用非 root 用户运行。
- Go 后端内嵌构建后的 Vue 静态资源，生产环境只增加一个控制台进程。
- SQLite 保存控制台账户、会话、设置和审计记录。
- AimiliVPN、3x-ui、Xray 与 Caddy 继续使用各自独立进程和更新机制。

适配器在 V1 中是控制台进程内的独立包，不单独部署 Sidecar。每个适配器只实现一个稳定接口，后续如果出现跨主机或独立发布需求，可以在不改变前端业务 API 的前提下拆分为独立服务。

### 6.2 技术基线

- 后端：Go，使用显式分层和标准 HTTP 接口。
- 前端：Vue 单页应用，生产构建产物由 Go 服务提供。
- 数据库：SQLite，启用事务、外键和必要的迁移版本。
- 入口：Caddy 提供 HTTPS、路由和基础安全响应头。
- 服务管理：systemd，控制台不以 root 运行。

具体 Go、Node.js、Vue 和依赖版本在设计批准后的实施计划中根据本机可用工具链锁定，不在设计阶段擅自安装或升级依赖。

## 7. 组件边界

### 7.1 Web 前端

前端只调用 Aimili Gateway 的版本化业务 API，不直接请求 AimiliVPN 或 3x-ui。主要页面包括：

1. 首次初始化与登录。
2. 系统总览。
3. AimiliVPN 节点与路由。
4. 多出口槽位。
5. 3x-ui 入站与客户端。
6. 入站到出口的绑定。
7. 脱敏日志与审计。
8. 控制台安全设置和专家模式入口。

前端不提供任意上游 API 代理、不保存服务凭据、不把敏感连接信息写入浏览器持久存储。

### 7.2 控制台业务 API

统一控制台使用 `/api/v1` 作为浏览器接口前缀。业务 API 负责：

- 验证控制台会话、CSRF 和请求参数。
- 将上游数据转换为统一领域模型。
- 执行能力检查、超时、重试和并发控制。
- 编排跨服务写操作并验证最终状态。
- 过滤敏感字段并记录脱敏审计事件。

业务 API 不向浏览器透传原始 3x-ui 或 AimiliVPN 响应。

### 7.3 AimiliVPN Adapter

AimiliVPN Adapter 面向统一业务层提供以下能力：

- 获取服务、主连接、节点池和代理出口状态。
- 查询、筛选、刷新和检测节点。
- 连接或断开节点。
- 查询和修改路由模式。
- 查询和管理多出口槽位。
- 获取经过字段白名单过滤的近期日志。
- 返回 AimiliVPN 控制 API 版本与能力集合。

为避免长期依赖原网页内部接口，AimiliVPN Fork 增加一个最小的、版本化的、仅回环监听的控制 API。它复用现有业务函数，不复制节点或隧道逻辑。控制 API 使用独立服务令牌认证，不复用 AimiliVPN 原生网页账户。

如果控制 API 版本或能力不受支持，适配器保持状态读取或完全降级，并禁止相应写操作。

### 7.4 3x-ui Adapter

3x-ui Adapter 通过本地 Web 管理 API 提供：

- 服务与 Xray 状态摘要。
- 入站列表、流量和启用状态。
- VLESS Reality 入站的受限创建与基础编辑。
- 客户端新增、编辑、启停、配额、到期时间和流量重置。
- 订阅或连接信息的按需生成和受控显示。
- Xray 出站与路由规则的读取、最小变更和结果验证。
- 运行版本、API 形状和能力探测。

适配器使用 Cookie Jar 和 CSRF 流程调用本地 3x-ui API，不直接读取或写入 `x-ui.db`。3x-ui 本地端点信息由部署配置提供；面板端口或路径改变后，由部署同步流程更新该配置。

V1 不托管 3x-ui 的 TOTP 秘钥。如果 3x-ui 已启用双重验证且没有经验证的 API Token 或独立自动化账户，统一控制台的 3x-ui 写操作必须降级为不可用，专家模式仍可正常使用。系统不得静默关闭 3x-ui 双重验证。

### 7.5 专家模式

专家模式是指通过 Caddy 保留原版 3x-ui 页面，并从统一控制台以新窗口打开。它不是嵌入式 iframe，也不由统一控制台注入登录态。

专家模式继续使用 3x-ui 自身用户名、密码、Cookie 和双重验证设置。统一控制台账户与专家模式账户相互独立。

### 7.6 AimiliVPN 原生维护入口

统一控制台达到 V1 验收标准后，AimiliVPN 原生网页不再作为常规公网入口，但服务和页面代码继续保留。维护时通过本机或 SSH 隧道访问，必要时可以临时恢复受控的 Caddy 路由。该调整不删除 AimiliVPN 功能，也不影响其独立更新和排障。

## 8. V1 功能范围

### 8.1 系统总览

- 控制台版本和运行时间。
- AimiliVPN、3x-ui/Xray 和两个适配器的状态。
- AimiliVPN 主连接、代理出口、有效节点数量和多出口槽位摘要。
- 3x-ui 入站数量、启用数量和流量摘要。
- 上游版本、适配器兼容性和需要用户处理的告警。

### 8.2 AimiliVPN 日常功能

- 节点列表、分页和国家、IP 类型、ISP 筛选。
- 节点刷新、单节点检测、连接和断开。
- 自动、固定地区、固定节点和收藏优先路由。
- 收藏或取消收藏节点。
- 多出口槽位列表、创建、启动、停止、删除、换 IP 和指定节点。
- 全局及单槽位国家、ISP 和住宅类型过滤。
- 主出口与槽位出口连通性检查。
- 经过白名单和脱敏处理的近期日志。

### 8.3 3x-ui 日常功能

- 入站列表、启用状态、协议、端口和流量。
- 启用或停用入站。
- 按受支持模板创建 VLESS Reality 入站。
- 编辑入站名称、端口和有限的模板参数。
- 客户端列表、新增、编辑、启停、配额、到期时间和流量重置。
- 删除入站或客户端时要求重新认证和明确确认。
- 订阅或连接信息默认遮罩，只允许用户主动显示或复制，不写入日志和审计详情。

复杂传输层设置、证书、任意 JSON、系统级设置和未受支持协议继续使用专家模式。

### 8.4 跨服务出口绑定

统一控制台允许把一个 3x-ui 入站绑定到：

- VPS 默认直连出口。
- AimiliVPN 主 SOCKS 出口。
- 一个指定的 AimiliVPN 多出口槽位。

绑定使用稳定的控制台资源标识，不把临时出口 IP 当作身份。控制台负责生成受管的 Xray outbound 和 routing rule，并使用明确的命名空间标记其所有权。它不得覆盖用户在专家模式创建的无关规则。

删除或停止被入站引用的槽位前，控制台必须显示依赖关系并阻止直接破坏；用户应先解除绑定或选择受控回退到默认出口。

## 9. 认证边界

### 9.1 统一控制台登录

统一控制台有自己的单管理员账户：

- 密码使用 Argon2id 哈希保存。
- 首次初始化通过服务器本地命令完成，不开放匿名公网初始化接口。
- 初始化时登记 TOTP，秘钥只显示一次，不写入普通日志。
- 登录成功后创建服务端会话，浏览器只保存不透明会话 Cookie。
- 会话支持空闲超时、绝对有效期、主动退出和全部会话撤销。

### 9.2 3x-ui 专家模式登录

专家模式仍由 3x-ui 自己认证。即使统一控制台与 3x-ui 恰好使用相同用户名或密码，它们仍是两个独立登录系统。

### 9.3 真正 SSO

真正 SSO 要求统一身份提供方签发身份，且统一控制台和 3x-ui 都正式验证该身份或共享受支持的会话协议。Caddy 外层认证、相同密码、自动填写表单或注入 Cookie 都不属于真正 SSO。

V1 不实现真正 SSO。只有在确认 3x-ui 提供可维护的 OIDC、SAML、受支持认证代理协议或可接受的上游扩展点后，才单独设计后续版本。

### 9.4 服务凭据

AimiliVPN 控制令牌和 3x-ui 自动化凭据是服务凭据，不是统一控制台用户密码，也不是 SSO 凭据。

- 服务凭据不保存到 Git、普通配置文件、SQLite 业务表或审计日志。
- 优先使用 systemd 加密凭据；不支持时使用权限严格的 root 管理文件作为回退。
- 控制台以专用用户读取运行时凭据，不在 API 响应或错误中返回凭据内容。
- 3x-ui 凭据按“经验证的 API Token、经验证的独立自动化账户、现有管理员凭据”的顺序选择。
- 当前本地证据只证明管理员网页登录流程可用，因此个人版 V1 的兼容回退是通过 systemd 加密凭据使用现有 3x-ui 管理员账户。这不等于统一账户或 SSO，并意味着控制台被攻破后可能获得 3x-ui 管理权限。
- V1 不保存 3x-ui 的 TOTP 秘钥。启用 3x-ui 双重验证且没有前两种自动化凭据时，3x-ui 写能力安全关闭，不自动降低专家模式的认证强度。

## 10. 安全模型

### 10.1 网络边界

- 只有 Caddy 的 HTTPS 入口对公网开放。
- Aimili Gateway、AimiliVPN 管理端、3x-ui 管理端和订阅后端保持回环监听。
- 多出口代理端口保持回环监听。
- 控制台不新增公网管理端口。

### 10.2 Web 安全

- 会话 Cookie 设置 `Secure`、`HttpOnly` 和严格 `SameSite`。
- 所有状态修改请求使用 CSRF Token，并验证 `Origin` 或 `Referer`。
- 登录、TOTP 和敏感操作实施速率限制。
- 修改服务凭据、删除资源和显示敏感连接信息需要重新认证。
- Caddy 和应用设置 CSP、禁止 MIME 嗅探、限制 iframe 和合理的引用策略。
- 前端不使用浏览器长期存储保存认证或连接秘密。

### 10.3 进程与文件权限

- 控制台以非 root 用户运行，无交互式 shell。
- SQLite、主密钥和运行时凭据使用最小文件权限。
- 控制台不得拥有修改 systemd 服务文件、Caddy 配置或 3x-ui 数据库的通用权限。
- 需要服务重启或部署变更时走独立、可审计的部署流程，而不是授予控制台任意命令执行能力。

### 10.4 数据和日志

- 审计日志记录时间、会话、动作、目标类型、目标脱敏标识、结果和错误分类。
- 不记录密码、Cookie、令牌、TOTP 秘钥、私钥、UUID、完整订阅链接或随机后台路径。
- 上游错误先经过字段过滤再写日志或返回浏览器。
- 敏感连接信息仅在用户主动请求时短暂返回，响应设置禁止缓存。

## 11. 数据模型

SQLite 只保存统一控制台自身状态：

### 11.1 管理员

- 唯一管理员记录。
- 用户名、密码哈希、TOTP 加密数据、创建时间和安全更新时间。
- 不包含租户、组织或角色字段。
- TOTP 加密使用的主密钥由 systemd 运行时凭据提供，不与密文一起保存在 SQLite。

### 11.2 会话

- 不透明会话标识的哈希。
- 创建时间、最后活动时间、绝对过期时间和撤销状态。
- 浏览器与 IP 的有限审计元数据，不保存完整请求头。

### 11.3 受管绑定

- 3x-ui 入站稳定标识。
- 目标出口类型和 AimiliVPN 槽位稳定编号。
- 最后一次验证状态和上游配置指纹。
- 不保存客户端 UUID、完整连接信息或订阅秘密。

### 11.4 审计事件

- 动作、资源、结果、错误类别、时间和会话引用。
- 详情使用字段白名单，敏感值在进入数据库前删除。

### 11.5 兼容性状态

- 最近探测到的服务版本、适配器版本、能力集合和探测时间。
- 最近一次不兼容原因和安全降级状态。

## 12. 适配器契约

统一业务层只依赖领域接口，不依赖上游 URL 或响应字段。两个适配器都实现：

- `Probe`：探测服务身份、版本、认证和能力。
- `Health`：返回健康、延迟和最近错误类别。
- `Capabilities`：声明当前可安全执行的读写动作。
- 领域读取方法：返回标准化对象。
- 领域写入方法：接收经过验证的命令并返回可验证结果。

适配器统一使用以下错误类别：

- `unauthenticated`：服务凭据无效或会话过期。
- `forbidden`：上游拒绝操作或缺少能力。
- `unavailable`：服务未运行或网络不可达。
- `incompatible`：版本、响应结构或能力不受支持。
- `invalid`：用户输入或上游约束无效。
- `conflict`：资源状态已改变或存在依赖。
- `timeout`：上游未在限定时间内完成。
- `verification_failed`：上游声称成功但重新读取未达到目标状态。
- `partial_failure`：跨服务操作只完成一部分，需要回滚或人工处理。

错误响应不得包含上游凭据、原始 Cookie、敏感配置或完整请求体。

## 13. 数据流与写操作语义

### 13.1 普通读取

1. 浏览器请求统一业务 API。
2. 控制台验证会话。
3. 适配器调用回环地址上的底层服务。
4. 适配器校验响应结构并转换为领域模型。
5. 控制台删除敏感字段后返回前端。

短期状态可以缓存数秒以降低轮询压力，但写操作前必须跳过缓存重新读取。

### 13.2 单服务写操作

1. 验证会话、CSRF、参数和必要的重新认证。
2. 检查适配器能力和兼容状态。
3. 读取最新上游状态并检查并发冲突。
4. 调用最小范围的上游 API。
5. 重新读取目标资源并核对预期字段。
6. 验证成功后记录审计并返回；验证失败则返回 `verification_failed`。

### 13.3 入站绑定到 AimiliVPN 出口

1. 读取 AimiliVPN 槽位和 3x-ui 入站的最新状态。
2. 验证目标槽位存在、已启动且本地代理可用。
3. 读取当前 Xray outbound 和 routing rule。
4. 只更新由 Aimili Gateway 命名空间管理的条目。
5. 调用 3x-ui API 应用配置。
6. 重新读取 Xray 配置，确认 outbound 和 routing rule 与目标一致。
7. 验证失败时尝试恢复修改前的受管条目；回滚也失败则记录 `partial_failure` 并禁用继续写入，直到用户处理。

AimiliVPN 槽位本身不因 3x-ui 写入失败而被删除，避免错误回滚中断其他引用者。

## 14. 更新与兼容性

### 14.1 AimiliVPN

- 继续使用 `main` 跟踪上游、`custom` 保存定制的分支模型。
- AimiliVPN 控制 API 使用独立版本号和能力列表。
- 上游同步后必须运行控制 API 合同测试和现有节点池测试，验证通过后才提升部署固定提交。
- 控制台不从移动分支自动更新生产 AimiliVPN。

### 14.2 3x-ui

- 首个适配目标为隔离环境中的官方 `v3.6.0`。
- 适配器维护已验证版本与能力矩阵，而不是仅比较版本字符串。
- 每次登录后探测关键只读端点和响应结构；只有所需能力全部匹配时才启用相应写操作。
- 用户通过原后台升级 3x-ui 后，控制台自动重新探测。未知或不兼容版本进入只读或禁用状态，专家模式不受影响。
- 不通过直接数据库读写规避 API 变化。

### 14.3 Aimili Gateway

- 控制台独立版本、独立发布和独立回滚。
- 数据库迁移必须向前兼容并在启动前备份。
- 控制台更新失败不得影响 AimiliVPN、3x-ui 或 Xray 继续运行。

### 14.4 一键更新边界

V1 不提供任何底层服务的一键更新按钮。统一控制台只显示版本、兼容性和建议操作；实际更新继续走各服务现有流程。这样可以先把核心管理闭环跑通，并避免把控制台扩大成服务器维护系统。

## 15. Caddy 路由设计

Caddy 按特异性优先处理：

1. 保留既有 3x-ui 专家模式入口。
2. 保留既有订阅入口。
3. 将 `/api/v1/*` 转发给 Aimili Gateway。
4. 其余普通网页请求由 Aimili Gateway 提供统一前端。
5. AimiliVPN 原生网页不作为常规公网入口。

Caddy 不替统一控制台或 3x-ui 伪造登录态。外层反向代理保护只能作为附加边界，不能描述为 SSO。

路由变更必须先生成候选配置、执行 Caddy 配置验证、原子替换并重新验证各入口；失败时恢复原配置。

## 16. 错误处理与降级

- AimiliVPN 不可用：3x-ui 页面和专家模式继续可用，Aimili 相关操作禁用。
- 3x-ui 不可用：AimiliVPN 页面继续可用，3x-ui 和绑定操作禁用。
- 适配器认证失败：显示明确的凭据状态，不反复高频登录，也不把上游响应原样返回。
- 版本不兼容：读能力按探测结果保留，写能力默认关闭。
- 上游超时：不假定失败或成功，重新读取状态后决定结果。
- 跨服务部分失败：记录可恢复状态，阻止重复写入，并提供进入专家模式的处理说明。
- 控制台数据库不可写：拒绝登录状态变更和所有写操作，底层服务继续独立运行。
- 控制台进程停止：Caddy 的专家模式和订阅入口继续工作；底层服务不依赖控制台保持运行。

## 17. 测试策略

### 17.1 单元测试

- 认证、会话、TOTP、CSRF、速率限制和重新认证。
- 领域验证、错误映射和敏感字段过滤。
- AimiliVPN 与 3x-ui 响应转换。
- 绑定依赖检查、受管规则合并和回滚计算。
- SQLite 迁移、事务和审计白名单。

### 17.2 适配器合同测试

- 使用本地假服务覆盖正常、认证失败、结构变化、超时和部分响应。
- AimiliVPN 控制 API 版本和能力合同。
- 3x-ui `v3.6.0` 的登录、CSRF、入站和 Xray 配置合同。
- 确认未知响应字段可忽略，缺少必需字段会安全降级。

### 17.3 隔离集成测试

- 在本地或隔离 Linux 环境运行控制台、AimiliVPN 测试实例和 3x-ui 测试实例。
- 验证登录、状态页、节点操作、槽位操作、入站和客户端操作。
- 验证入站绑定、解除绑定、冲突、失败回滚和重启后的持久状态。
- 验证 3x-ui 升级为未知版本后写能力关闭而专家模式仍可访问。

### 17.4 前端测试

- 主要页面和表单的组件测试。
- 敏感信息遮罩、主动显示和复制流程。
- 服务不可用、认证过期、版本不兼容和部分失败状态。
- 桌面与窄屏布局的基本可用性。

### 17.5 安全测试

- 未认证访问、CSRF、会话固定、暴力登录和越权接口。
- 日志、审计、错误响应和浏览器存储的秘密扫描。
- Caddy 路由旁路和直接公网端口检查。
- 控制台专用用户的文件与进程权限检查。

### 17.6 端到端验收

完成声明必须沿用户真实操作路径验证：

1. 浏览器登录统一控制台。
2. 查看两个服务的实时状态。
3. 操作一个 AimiliVPN 节点或槽位并确认真实状态变化。
4. 管理一个测试入站或客户端并由 3x-ui 重新读取确认。
5. 将测试入站绑定到 AimiliVPN 出口，并验证真实流量从目标出口离开。
6. 打开专家模式并确认仍需 3x-ui 自身登录。
7. 重启控制台，确认底层服务不中断且控制台状态可恢复。

生产 VPS 只有在用户再次明确授权后，才进行新的只读基线、备份、部署和上述端到端验收。历史状态不能替代本次验证。

## 18. 发布与回滚边界

正式部署时，统一控制台作为新增服务接入，不能直接替换或删除现有入口。切换顺序应保证：

- 安装控制台失败时，原版 3x-ui 和 AimiliVPN 保持原状。
- Caddy 路由变更失败时可恢复原配置。
- 统一页面验证通过后再限制 AimiliVPN 原生公网入口。
- 任何阶段都保留 3x-ui 专家模式和订阅服务。
- 卸载控制台只删除其服务、路由和自身数据，不删除两个底层服务的数据。

具体部署步骤、命令、备份位置和回滚操作属于实施计划，须在本文批准后另行编写。

## 19. 风险与控制措施

### 19.1 3x-ui API 不稳定

控制措施：版本与能力探测、合同测试、字段白名单、安全降级、专家模式保留，不直接访问数据库。

### 19.2 控制台持有高权限服务凭据

控制措施：非 root 进程、运行时加密凭据、回环网络、最小接口、日志脱敏、重新认证和审计。无法使用独立服务账户时，文档和界面明确提示权限风险。

### 19.3 跨服务配置部分成功

控制措施：操作前快照、受管命名空间、写后重新读取、有限回滚、部分失败锁和专家模式恢复路径。

### 19.4 AimiliVPN 公共节点波动

控制措施：界面区分“服务运行”“隧道连接”和“真实出口可用”，不把节点短暂失败误报为控制台故障。

### 19.5 范围继续膨胀

控制措施：V1 坚持单管理员、受限协议模板、无一键更新、无服务器全面运维；新增能力在核心闭环验收后单独评审。

## 20. V1 验收标准

V1 必须同时满足：

1. 一个控制台管理员账户能够登录并启用 TOTP。
2. 统一首页能够区分并显示两个服务、Xray 和适配器的真实状态。
3. AimiliVPN 的节点、路由和多出口常用操作可用，并有写后验证。
4. 3x-ui 的入站和客户端常用操作在受支持版本上可用，并有写后验证。
5. 可以将入站绑定到 AimiliVPN 主出口或多出口槽位，并验证真实出口。
6. 专家模式继续使用 3x-ui 自身登录；系统没有把相同密码或 Caddy 保护描述为 SSO。
7. 不兼容版本会安全禁用写操作，不影响底层服务独立运行。
8. 日志、审计和 API 响应不泄露敏感凭据或完整连接秘密。
9. 控制台停止或回滚不会停止 AimiliVPN、3x-ui、Xray、订阅或专家模式。
10. 生产部署前取得新的明确授权并完成新鲜基线、备份和端到端复测。
