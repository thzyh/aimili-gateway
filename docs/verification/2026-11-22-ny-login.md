- 项目锁定 `modernc.org/sqlite v1.38.2`。对照其实际缓存源码，取消查询的 deferred cleanup 会把已创建的 Rows 直接丢弃，没有 Close，导致连接上的语句和读事务残留。[上游修复 !81](https://gitlab.com/cznic/sqlite/-/merge_requests/81) 明确说明同一泄漏，v1.40.1 包含取消时关闭 Rows 的代码。
- 新增 `TestCanceledQueryReleasesSessionSnapshot`：在临时 WAL 数据库中，通过同步的 SQL 函数等待查询实际开始，再取消上下文；由另一连接创建会话，检查原连接能否读取新会话并完成 checkpoint。原 v1.38.2 稳定失败，报 `interrupted (9)`，测试数据库也因残留句柄无法立即删除。这里没有用修改生产数据或伪造 HTTP 响应复现。
- 用户明确授权后，仅升级项目内 SQLite 到 v1.40.1、其所需 libc 到 v1.66.10 和 x/sys 到 v0.36.0。同一用例连续 5 次通过，随后 `go test ./...` 全部通过。修复使用上游原生实现，没有自建连接重试层或放宽会话认证。
- 确认该缺陷可以使长时间运行的连接在取消请求后失效，并且关闭连接后恢复；符合原来的长期运行异常和重启恢复。**旧进程在诊断前已退出，未留下内部错误原因，因此不能把此实验表述为现场每一个 401 已获得排他证明。** 当前修复消除了已复现的驱动缺陷，保留脱敏日志用于确认其他拒绝分支。
