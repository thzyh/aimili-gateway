## 外部客户端与真实链路

### VLESS Reality

使用 Gateway 导出的受管 VLESS Reality 材料生成一次性本地 Xray 配置，通过公网入口完成：

- VLESS Reality 握手。
- 代理端 DNS 解析。
- 公网出口与 Gateway 记录出口一致。

最终标记为 `FINAL_VLESS_REALITY_PROXY_DNS_EXIT_PASS`。一次性 Xray 进程和本地配置已清理。

### SOCKS5H

在原策略为开启且包含 2 条 CIDR 的前提下：

1. 通过认证的 Gateway API 临时将来源限制关闭，返回 HTTP 200，状态为 `applied`。
2. 从本机对两个独立公网 IP 查询服务发起 SOCKS5H 请求。
3. 两次请求均使用代理端 DNS，且出口与 Gateway 记录一致，标记为 `SOCKS5H_PROXY_DNS_EXIT_PASS`。
4. 立即恢复原策略，返回 HTTP 200，状态为开启、`applied`、2 条 CIDR。
5. 恢复后本机外部来源再次被拒绝。
6. 数据库二次确认最终策略为 `1:applied:2`。

原 SSH 交互会话曾在发送恢复命令前被远端关闭；当时立即暂停其他验收，通过新 SSH 连接恢复原策略，并完成数据库与外部拒绝双重验证。最终安全边界已确认恢复。

## 换 IP 与故障恢复边界

真实“换 IP”操作曾调用多个同国家/类型上游 VPN Gate 候选；候选出现连接超时或无路由，原在线组因此按设计进入 `degraded`。检查未发现 VPS OOM 或 512 MiB 内存限制导致该失败。

在原组无法恢复后，系统回收故障组并依次启用其他候选，第三个候选成功建立新在线组；随后 Gateway 节点检查为 HTTP 200、状态 `ready`，VLESS Reality 公网链路再次通过。

因此已验证：

- 换 IP 失败会被识别并标记，不会伪报成功。
- 故障组可以回收并通过新候选恢复服务。
- 恢复后的 VLESS、代理 DNS 和出口一致性可用。

没有获得“同一组 rotate API 在上游候选可用时成功返回”的独立成功样本；这是免费上游候选当时不可用造成的真实环境限制，不是尚未实现的 V1-D 代码项。生产使用不能把免费 VPN Gate 节点的持续可用性视为保证。

## 安全边界

- 三服务使用相同用户名和密码，但各自保留独立会话，不称为真正 SSO。
- Gateway TOTP 只保护 Gateway 登录，不同步到底层服务；当前已关闭。
- 3x-ui 自身 TOTP 保持关闭，以兼容受控自动代登录。
- SOCKS5H 即使关闭来源限制仍要求强随机用户名和密码；本次验收结束后已恢复来源限制。
- Gateway 不在浏览器中自动填表，不把密码写入 DOM、URL、前端存储、日志或文档。
- 3x-ui、Xray 与 AimiliVPN 继续独立更新和运行；V1-D 没有重写核心或合并进程。
