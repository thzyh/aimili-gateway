## 部署前门禁

部署前只允许保留一份带时间戳的 bj 备份，备份 Gateway 二进制、egress 源码目录、systemd unit 和 Gateway/egress 配置；不覆盖 3x-ui/Xray 数据库，不删除现有 OpenVPN 配置。门禁必须记录：

1. `systemctl is-active aimili-gateway aimilivpn x-ui caddy`。
2. 当前 OpenVPN/TUN、Gateway 监听端口和出口真实检测结果。
3. 内存、Swap、根分区可用空间、最近 OOM/服务重启。
4. 备份路径、文件摘要和回滚命令。

## 4+4 阶梯验证

部署后先只启动当前活动连接对应的动态备用目标，确认容量接口没有把暂停槽位计入目标；再观察所有目标进入 `ready` 或给出明确的 `resource_pressure`/`manual_required` 原因。若资源上限低于请求值，必须保留现有活动出口并安全拒绝新增。

通过容量门禁后，逐个受控验证一个出口：记录故障前的节点 ID、出口 IP 和其他出口摘要；让单个活动隧道失效；确认对应备用完成提升，其他出口节点 ID 与出口 IP 不变；确认后台为同一目标补回新的备用。不能同时操作多个出口，也不能手工删除数据库记录来制造通过。

最后重启 `aimilivpn.service` 和 `aimili-gateway.service`，检查恢复状态、备用数量、路由、监听、真实出口和日志。任何失败都记录第一失败边界，优先回滚到部署前备份；不修改 jjs/xjp。

## 本轮锁竞争修复

池耗尽后台线程原先只尝试一次非阻塞 mutation lease；它通常在自动切换尚未释放锁时直接返回 `operation_busy`，导致补池丢失。现改为最多约 2 秒的短时有界重试，锁释放后继续维护，独立长事务仍会安全延后。对应回归已纳入 Python 全套 295 项测试。
