# 整项目更新流程修复

## 问题与范围

- jjs 运行 `eea92cb` 基础版本，构建版本为 `dev`，旧界面把完整 VPS 包当成单个 Gateway 二进制发布，从而报“缺少签名文件”。
- 先前仅在 xjp 修改提示，没有让 jjs 获得“确认并安装最新项目”的能力，不能视为本需求完成。
- 用户允许给 jjs 安装更新入口补丁；目标项目版本的实际升级必须留给用户点击。不得在验收时调用 jjs 的 apply 接口。

## 实现

- API 新增经过会话、Origin 和 CSRF 校验的检测请求；现有事务客户端复用独立 `project-update` 队列，避免旧更新器接管。
- 无权限下载服务从固定 GitHub 仓库下载；root 服务仅能访问回环网络，复制到私有目录后重新验证 Ed25519 签名与 SHA256。
- 固定安装路径，拒绝压缩包越界、链接和重复文件；不执行首次初始化、不重建入站、不生成新 UUID。
- 停服后备份 SQLite、配置、程序和出口状态。失败或中断后恢复旧程序和数据库；恢复未确认时阻止后续安装。
- 数据库 quick_check、服务、监听端口、Gateway 健康及连接身份核对通过后才记录成功。
- 页面确认前不安装，显示真实阶段和下载进度，刷新或短暂断线后继续查询原事务。
- 构建器写入准确的版本、提交和构建时间，解决发布二进制一直显示 dev 的问题。

## 当前验证

- Go 全量测试通过。
- 前端 86 项测试通过；确认取消、仅一次 apply、刷新恢复、重启重连及回滚提示均有测试。
- Python 6 项测试通过，包含真实 OpenSSL 签名篡改拒绝、路径攻击拒绝、成功安装与健康失败后的数据库恢复。
- 前端生产构建通过。
- 复杂度审查：复用现有事务与系统 timer，未新增第三方依赖；保留下载/安装权限隔离和独立请求队列。
- 生产补丁部署、发布和用户验收结果待补充；上述测试不代表 jjs 已升级。
