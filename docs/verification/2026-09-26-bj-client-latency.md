## 本轮直接证据

北京时间 2026-09-26 17:46:27–17:48:24，使用与 v2rayN 7.24.4 相同的 .NET `SocketsHttpHandler`，每节点两次 HTTP 请求，复用连接，总上限均为 9 秒。交错执行三种条件，五节点各两轮。

| 条件 | 成功 | 失败 | 说明 |
|---|---:|---:|---|
| 原 HTTPS 地址，连接上限 3 秒 | 7 | 3 | 失败内层异常均为 `A connection could not be established within the configured ConnectTimeout` |
| HTTP 204 地址，连接上限 3 秒 | 8 | 2 | 主出口出现响应提前结束，不能作为可靠替代 |
| 原 HTTPS 地址，连接上限 8 秒 | 10 | 0 | 只改变连接上限；仍须两次真实 HTTP 204；总上限保持 9 秒 |

8 秒条件覆盖主出口、出口 1–4。首次请求最大实测约 5.86 秒，第二次通常约 0.45–0.62 秒；两轮全通过只证明本轮有效，不保证未来网络故障永不出现。

bj 同时段的五个实际出口（本机 SOCKS 7928、17928–17931）全部返回 Google HTTP 204，耗时约 0.65–1.07 秒；这些才是出口引擎端口。30000–30003 是要求认证的公网 mixed 入站，未认证请求被拒绝不能算出口失败。

服务器抓包与临时 Xray 调试日志按时间对齐。失败样本存在 TCP 已建立但客户端协议握手未及时完成；此前样本还有重传。可确认短连接超时参与失败，尚未定位全部抖动的具体物理网络区段。
