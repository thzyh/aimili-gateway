# ny 日本候选检测与内置浏览器排障

## 国家检测根因

- 2026-11-02 北京时间 09:42:43、09:53:33 各提交一次 JP 检测。前一次拉取 48 条候选，后一次官方仍为 48 条，但进入检测只剩 27 条。两轮日志分别有 11、6 次 OpenVPN `AUTH_FAILED`，证明部分探测被远端拒绝，不能宣称全部节点实际健康。
- 第二轮结果记录测试 23、成功 16、失败 7，却声称保留 47 条日本可用记录。其中 7 条仍被冷却过滤；原始记录、API 完成计数和实时可见列表存在差异。
- 根因一：手动完整检测虽然在队列层忽略冷却，但 `fetch_candidates()` 先过滤了冷却候选，队列层无法重测它们。
- 根因二：`rebalance_valid_pool()` 的遍历顺序让旧记录覆盖本轮成功结果，出口 IP、类型和检测时间未更新；本轮失败旧记录仍被当成可用参与合并。`read_nodes()` 又过滤新冷却记录，造成完成计数虚高。旧合并顺序自整合提交 `7eeaf43` 已存在，手动绕过队列冷却见 `e9577a1`；不是本次 0.2.46 新增的初始化修复所引入。
- 国家统计另按真实出口 IP 去重，可替换候选还排除活动连接、热备用及相同出口 IP；不能把官方记录数、有效缓存数和未占用候选数当成同一口径。
